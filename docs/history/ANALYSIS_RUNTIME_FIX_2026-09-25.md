## Подтверждённые причины и изменения

1. Preparation 3acce68064fb4e2e9a0ae322f21022ca (VK Education): Arial был найден
   в /System/Library/Fonts/Supplemental/Arial.ttf, но fsType=8 ошибочно приводил
   к waiting_fonts. Local-only ранее учитывался для Office DFonts и Aptos,
   но не этого установленного системного шрифта. Теперь установленный шрифт
   с ненулевым fsType используется локально без распространения файла шрифта.
   Флаг fsType не меняется. Проверки встроенных/загруженных шрифтов не ослаблены.
   Реальный Education: 65 макетов, required_missing=[], Arial и Consolas local-only.
   PPTX сохраняет редактируемый текст; при local-only HTML/PDF используют существующий
   безопасный режим отрисованных страниц без включения файла шрифта.

2. Preparation 75c341e5b019473997633027610ba75f (Workspace): eager gather ставил все
   группы в общий сериализованный provider gate. В журнале ожидание 1156.93s плюс
   76.376s реального запроса, отдельные запросы падали через 180s и разветвлялись
   на повторы/одиночные макеты. UI показывал старый retry вместо реального прогресса.
   Теперь группы анализируются последовательно. В одном запросе максимум одно
   исходное изображение (связанные макеты той же картинки могут оставаться вместе).
   Текстовые layout-группы ограничены четырьмя макетами: реальная группа из 15
   исчерпала ответный бюджет даже без изображений. Обрезанный ответ большой группы
   теперь сразу дробится, а не повторяется целиком.
   Показывается фактическое число обработанных макетов, а не заранее последний offset.
   Большая группа после transport timeout сразу дробится, без идентичного повтора.
   После двух последовательных провалов одиночных групп при недоступном провайдере
   анализ останавливается с понятной причиной и сохранёнными успешными checkpoints.
   Cache hit не считается восстановлением API. Неисправимые HTTP 4xx не размножают вызовы.
   Общего дедлайна анализа/генерации по-прежнему НЕТ. Дедлайн одного запроса — 180s.

3. При тестировании отклонён чрезмерно тесный новый ответный бюджет 768+thinking:
   он обрезал часть ответов. Итоговый запас для template_analyst: минимум 4096
   токенов ответа; при большом batch увеличивается.
   Повторный live тест выявил length даже в группе 4 при thinking=512.
   Поэтому только template_analyst теперь enable_thinking=false (бюджет 0).
   Движок и модель не подменяются: qwen3.8-27b. Reasoning для генерации,
   критики и ремонта сохранён. Это не обещание ускорения самого провайдера.
   finish_reason и безопасные числовые token counters теперь логируются и при
   обрезке ответа. reasoning_content и сырые ответы не логируются.
