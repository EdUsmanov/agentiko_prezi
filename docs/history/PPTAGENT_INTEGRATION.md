# PPTAgent / DeepPresenter: интеграция в Forma

Обновление 24.09.2026: центральный процесс перестроен вокруг общей структуры документа, паспортов назначения макетов и ограниченного цикла render/review/repair. Подробности и актуальные границы: [SEMANTIC_PIPELINE_V2.md](SEMANTIC_PIPELINE_V2.md). Смысловой анализ шаблона теперь получает исходные изображения, отдельная финальная VL-проверка — исходный референс и результат. Адаптер Design остаётся ограниченным, это не полный upstream продукт. Описанные ниже первоначальные ограничения по отсутствию собственного визуального цикла относятся к первой интеграции.

Дата: 23.09.2026. Пользователь поручил адаптировать новый runtime и при необходимости старый.

## Что внедрено

Подключён реальный цикл `Agent.action/execute` и `Design.loop` из DeepPresenter, tag `v1.1.38`, commit `2e68c095a86bdbb91635dc4d91dad4662aba163c`. Это ограниченный fork, не полный upstream продукт. Минимальный MIT-код хранится в `studio/_vendor/deeppresenter`, изменения перечислены в PROVENANCE.md, лицензия сохранена.

Design выбирает исходные композиции под уже проверенный semantic deck, получает результаты детерминированного аудита и может исправить выбор. Нативный template-aware renderer, интерфейс, история, шрифты, immutable package, проверки и общий дедлайн остаются нашими. Старый сторонний PPTAgent не понадобился; собственный прежний движок доступен как `native`.

Принципиальное ограничение: интеграция не переносит качество полного upstream автоматически. Здесь нет его Research, свободной HTML-вёрстки, визуальной кластеризации, VLM reflection и template induction всех объектов. Версия/модель, которую тестировали коллеги, пока неизвестна; сравнительный выигрыш по дизайну не подтверждён.

## Два этапа и контракт

```text
Подготовка без конкурсного лимита
  PPTX → ZIP/XML validation → tokens, source patterns, font, artwork cache
  текст → факты/таблицы/ограничения → LLM semantics + проверенный план
  → immutable PreparedPackage

Генерация: общий дедлайн 300 секунд на три презентации
  frozen plans → DeepPresenter Design (до 90 секунд / 6 ходов)
    compose_slides: полный набор variant + slide + pattern_id
    inspect_variants: аудит текущей ревизии
    finalize: только после успешной инспекции текущей ревизии
  → native Scene → repair + diversity + повторный audit
  → PPTX / HTML / PDF / previews → critic → manifest + ZIP
```

Модель не переписывает факты, заголовки, порядок, шрифты или палитру на стадии Design. Она назначает только существующие пригодные pattern IDs либо token:auto — ограниченную композицию из токенов загруженного шаблона с явной проверкой соответствия стилю. Выбор хранится в SlidePlan.pattern_id и действительно соблюдается composer, а не остаётся рекомендацией. Все три варианта обязательны, частичные/дублирующиеся назначения отвергаются. Изменение плана атомарное; geometry guard заменяет ухудшающие вместимость назначения проверенным baseline и фиксирует каждую правку. Если безопасный результат невозможен, изменение не принимается. После изменения предыдущая инспекция становится недействительной.

Резерв на экспорт/critic — 150 секунд. Весь Design ограничен 90 секундами и 6 ходами; обычно три хода и один запрос к модели. Запрос выбора композиций использует оставшийся бюджет Design с резервом до 5 секунд на локальные проверки (в обычном случае — около 85 секунд). Прежний независимый таймаут 35 секунд удалён. Модель выбирает композиции; inspect → finalize выполняются кодом через тот же проверяемый цикл инструментов, без двух лишних запросов к LLM. Время входит в общий generation job. Если upstream не завершил проверенную композицию, запуск получает явную ошибку без скрытого fallback. Старые подготовленные пакеты без frozen plans поддерживаются через ограниченное планирование; если на Design и экспорт уже нет бюджета, неполный результат не считается готовым.

## Безопасность и модели

- Окружение агента: только compose_slides, inspect_variants, finalize. Никаких shell, eval, файловых путей, сетевых fetch, installs, HTML/JS или Docker socket.
- GatewayBridge преобразует строгий JSON в один tool call. Локальная allowlist и валидация обязательны независимо от prompt.
- Inference идёт через прежний ModelGateway: открытые веса ≤35B, server-owned endpoint, на финале VK allowlist.
- Ключ не попадает в контекст или upstream config. OpenAI SDK нужен только для совместимых типов сообщений, а не для использования моделей OpenAI.
- Сам Design не получает изображения или PPTX: только факты, геометрию и очищенные описания. Отдельный opt-in visual critic Studio получает PNG готовых слайдов после разрешения на передачу; это не upstream VLM reflection. Nested history и тексты в изображениях остаются недоверенными данными.
- Upstream debug/reasoning/history отключены. Manifest содержит операции, тайминги, commit и хеши исходников/prompts/configs.
- Это прикладное ограничение полномочий, не OS sandbox. Нативные parser/renderer по-прежнему требуют отдельной OS-изоляции при публичном внедрении.
- Качество геометрии и реальный PDF-рендер не называются VLM-проверкой.

## Как запускать

```bash
python -m pip install -r requirements.lock
python -m studio.cli serve --port 8765
```

Для editable-установки: `python -m pip install -e '.[deeppresenter]'`.

В API-режиме по умолчанию `STUDIO_ENGINE=deeppresenter`; в автономном — `native`. Явное `STUDIO_ENGINE=native` возвращает прежний движок после перезапуска. Независимо от выбора сохраняются новые семантическая подготовка, проверки diversity и UI. Health показывает активный engine и readiness. Отсутствующие зависимости дают 503 до старта генерации, а не позднюю подмену движка.

Установлены только четыре прямые зависимости адаптера и их небольшой dependency closure. Полный `pip install pptagent`, upstream `onboard`, системные установщики и Docker не запускались.

## Почему не встроен старый runtime

В классическом v0.2.0 (commit `d53296bc0ddd73e81d51c523d20dd711c7f233f3`) executor вызывает `eval` модельной программы после проверки имени внешней функции. Это не безопасная изоляция. Его набор per-slide content_organizer/layout_selector/editor/coder также делает штатные три запуска дорогими по времени. Для полного template engine потребуются отдельные объектные схемы и безопасный JSON EditPlan, а не включение eval.

Переиспользовать induction/classification старой версии можно следующим этапом, если A/B докажет выигрыш. Сейчас новый ограниченный Design работает без неё; лишний runtime не добавлен.

## Проверки и дальнейшие границы

Синтетический живой прогон: подготовка 20.443 секунды, три колоды по 3 слайда — 13.962 секунды, completed, 0 ошибок, три разных fingerprints, текстовый critic выполнен. Это малый тест, не SLA на произвольные PPTX.

Контрактные тесты проверяют реальный upstream цикл на mock gateway, неизменность фактов, точное применение pattern IDs, atomic rollback, неизвестные операции/пути, запрет преждевременного finalize, повторную инспекцию и отмену по таймеру. Итоги расширенного прогона и аудита записываются в TEST_REPORT.md и CODE_AUDIT.md.

Для доказательства дизайнерского превосходства нужны одинаковые входы и экспертное A/B с проверенной коллегами конфигурацией, в том числе на неизвестном шаблоне. Не выполнены VLM/OCR проверки выходных слайдов, сложные image-driven layouts, финальный T2I и OS sandbox. Они не скрыты за статусом нового runtime.
