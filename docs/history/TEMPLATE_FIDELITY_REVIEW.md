# Макеты, цвета текста и смысловые разделители — 24.09.2026

## Причины дефектов

- После извлечения цвета текста рендер фона заменял его самым контрастным цветом общей палитры. На светлом фоне получался чёрный независимо от исходного элемента.
- Для трёх вариантов принудительно назначались одинаковые политики вёрстки. Одна исходная текстовая зона могла искусственно делиться на колонки.
- В презентациях без плейсхолдеров маленькая верхняя подпись принималась за заголовок. Часть цветных раскладок исключалась из-за дефектов исходной геометрии.
- Заголовки «Слайд N» безусловно отключали разделители. Проверка размещения пробовала только одну пару для объединения и могла отклонить вставку из-за ошибки на другом слайде.

## Исправления

- Новый адаптер native_style разрешает цвет конкретного текстового объекта через slide → layout → master → theme, включая clrMap, преобразования цвета и пустые плейсхолдеры POTX. Для многоцветного текста используется преобладающий по объёму текста цвет; посимвольное копирование стилей не заявляется.
- Исходный цвет сохраняется после рендера фонового слоя. Низкий контраст остаётся предупреждением, а не поводом автоматически перекрасить бренд.
- Native-композиция сохраняет количество и расположение исходных зон. Разделение одной зоны допускается для комбинации таблицы и пояснения, но не по одному лишь имени варианта.
- Выбор заголовка учитывает размер шрифта. Пересекающиеся и выходящие за край области консервативно обрезаются внутри исходных прямоугольников; неподходящие макеты по-прежнему отбрасываются.
- Наблюдаемые в примерах мастера получают приоритет. Ограниченный DeepPresenter не может заменить безопасную исходную композицию неиспользуемым мастером или token:auto без восстановления базового решения.
- Различия вариантов сначала обеспечиваются альтернативными нативными раскладками того же мастера, затем безопасным переразмещением внутри зон. Отсутствие безопасного варианта не уничтожает план.
- Для нумерованного плана отдельный шаг LLM во время подготовки выделяет 2–4 смысловых раздела. Валидатор требует полного покрытия и исходного порядка. Для обычных Markdown-разделов дополнительный вызов не нужен.
- Разделители берутся из пользовательского шаблона. Для освобождения места проверяются разные пары соседних текстовых слайдов одного раздела. Сохраняются число слайдов, все факты и порядок нумерованного источника. Если безопасного места нет, добавляется предупреждение.
- Цвет, шрифт и размер буллитов задаются явно в PPTX.
