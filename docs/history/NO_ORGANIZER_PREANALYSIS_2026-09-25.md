# VK Forma: удаление анализа библиотеки VK — 25.09.2026

## Решение и эффект

По прямому запросу пользователя предварительный анализ трёх организаторских
шаблонов удалён из обеих веток. У него были только два потребителя: точное
переиспользование семантики совпадающего по SHA шаблона и до 64 абстрактных
наблюдений для планировщика. Библиотека не обучала модель и не переносила
чужие стили в пользовательский шаблон. Положительный эффект на качество
неизвестного шаблона не был подтверждён A/B-измерением.

Удалены фоновые worker/monitor, требование готовности библиотеки, её endpoints,
команда пересборки, UI-контролы и organizer hints в planner. Остановлены два
уже работавших builder-процесса. Исторические snapshots, исходные файлы,
кэш и журналы не удалялись. Запись последней попытки помечена cancelled с причиной.

## Сохранённые возможности

- Полный технический и смысловой анализ выбранного пользователем PPTX/POTX.
- Шрифты, палитра, композиции, portable-инструменты и проверки готовых файлов.
- Проверенный per-input analysis-cache, независимо от организаторских примеров.
- Автогенерация через 60 секунд и отсутствие общего дедлайна.
- Журнал текущего/прошлых пользовательских заданий с редактированием секретов.
- Необязательный выбор одного из демофайлов. Он анализируется только после выбора.
- Защита от нового анализа на устаревшем процессе; статус GET /api/runtime.

Регистрация демофайлов перенесена в studio/examples.py: проверяет безопасность
контейнера и сохраняет оригинальные байты, но не анализирует оформление,
не рендерит и не вызывает модель. Общие версии/атомарная запись вынесены в
studio/cache_version.py; зависимости от удалённого reference_library отсутствуют.
Два ручных API smoke-скрипта PPTAgent также больше не ждут библиотеку.
