# Объединение main с модульным backend

Ветка `codex/variant-structure-template-tables` объединяет рефакторинг `fd52d48` с `main` на `60bc5ac`. В репозитории нет ветки `master`; актуальная основная ветка — `main`.

## Разрешение конфликтов

| Из main | Размещение после слияния |
|---|---|
| Ручной запуск одного или трёх вариантов | `api/schemas.py` → `PresentationService.generate` → атомарная резервация `Store` → `generation/planning.py` |
| Повторное использование сохранённого шаблона | HTTP разбирает `source_package_id`; сервис проверяет пакет и копирует исходник нового задания |
| Предварительный анализ библиотеки | `preparation/reference_analysis.py` использует общий технический и семантический путь `preparation/template.py` |
| Удаление истории | Тонкий маршрут, прикладной сервис, транзакция `Store.delete_tree`; учитываются версии брифа и адресного ремонта |
| Адаптация фонов, диаграмм, таблиц и читаемости | Модули `composition/`; проверки пригодности и отсутствия ухудшений — `checks/` |
| Оформление интерфейса и сохранённые дизайн-системы | Существующий frontend; утверждение брифа, предварительный анализ, ресурсы и аудит черновика сохранены |

`app.py` остаётся фабрикой приложения. Маршруты не вызывают pipeline и не обращаются к внутреннему хранилищу сервиса. Runtime остаётся владельцем задач и процессов. Старые плоские модули и совместимые реэкспорты не возвращены.

Новые пакеты запускаются вручную. Для брифа обязательны точные хеши утверждённого плана и текста. Таймеры существующих пакетов поддерживаются, но удалённый пакет не запускается и не получает поздние события. Дедлайн генерации из main — 300 секунд; подготовка находится за его пределами.

## Сохранённые гарантии

- Различия вариантов проверяются по структуре фактического PPTX и связи с источниками. Сдвиг объектов или смена названия макета не доказывают различие.
- Нативные табличные шаблоны сохраняют геометрию, стили и редактируемые ячейки; старый текст не переносится.
- Семантические подписи остаются при преобразовании композиции; аудит проверяет и текстовые объекты, и таблицы сравнения.
- Снимок итогового аудита содержит только реально выбранные варианты. Ремонт наследует число вариантов исходной генерации.
- PPTX остаётся главным результатом; выбранные PPTX находятся в корне ZIP.
- Зависимости кешей обновлены; архитектурный тест проверяет пути, циклы и границы HTTP рекурсивно.

Исторические отчёты main перенесены в `docs/history/`; их результаты не являются проверкой объединённой версии.

## Replay

Синтетическая кассета браузерного сценария обновлена после изменения схемы групп, промптов, названий вариантов и разбиения визуального аудита. Исходные ответы редактора и исходные факты сохранены. Ответы визуального проверяющего лишь подтверждают запрошенные номера слайдов и не служат доказательством качества реальной модели. Обычный тест воспроизводит конечную кассету строго, без записи и сетевого fallback.
