# External PowerPoint template validation — 2026-09-28

## Scope and evidence

Eight real university templates were downloaded for **local compatibility testing only**. The files are ignored by Git. The [corpus manifest](../test-results/external-template-corpus/manifest.json) records each source page, direct download URL, SHA-256, file size, format, aspect ratio, and a ZIP/slide/layout/font inventory. The source pages do not state a redistribution license, so the template files are not part of this repository.

| Institution | Local template | Distinguishing case |
| --- | --- | --- |

| [Arkansas State University](https://kb.astate.edu/books/university-templates/page/powerpoint-templates) | `astate-dark.pptx`, `astate-light.pptx` | Paired dark/light, 21 slides each, many pictures |

All eight files passed ZIP integrity and contained `ppt/presentation.xml`. The end-to-end harness uses isolated HTTP and workers, uploads each real file, analyzes twice, prepares content, generates three variants, and checks native PNG, PPTX, PDF, HTML, ZIP, history, and diagnostics. Its artifacts are under `test-results/external-template-runs/`.

## Extractive runs and repaired failures

Each of the eight templates has a later **passing extractive/native HTTP run**. These are smoke tests without paid model calls; `needs_review` can still be the correct generation state when review findings remain.

Earlier failures remain in the run directory as negative evidence:

- A-State dark/light and Binghamton initially failed template analysis because a picture placeholder was read through `.text_frame`. A guarded text-frame fix was followed by passing reruns.
- WSSU and USI initially failed typography-scale extraction. The font/scale fix was followed by passing reruns.
- WPI initially exported the 3×3 sample shapes from its authored “Default Settings” reference page into content slides. A source-evidence classifier now marks that page and the “Color Scheme” swatch page `reference` and `reusable=False` before derived layouts are made. The [WPI rerun](../test-results/external-template-runs/wpi-widescreen-content-08975929-02334700fb-20260928T182647Z/summary.json) passed; all three `slides.json` files avoid source slides 19–20, while the WPI line, logo, and colors remain visible. Fourteen targeted reference/template regression tests passed.
- An early Adelphi cache/history assertion was corrected in the harness. HTTP 503 responses during concurrent code changes were version-staleness signals and were rerun on fresh servers; they are not counted as template defects.

Passing HTTP checks establish that the pipeline can process these files and produce readable artifacts. They do **not** establish that every design or semantic requirement is met.

I inspected the actual native PNGs for the image and data slides in each of the three variants, and the PPTX shapes and embedded image pixels.

## Synthetic OLE preview regression

A separate **synthetic OOXML** presentation reproduced loss of a visible decorative OLE preview: the background extractor treated its `p:graphicFrame` as structured content and removed it from both the background and editable source. The boundary adapter now turns only a packaged, static preview under `p:oleObj` (including `mc:AlternateContent/Fallback`) into `p:pic`, preserving the outer shape ID and transform while dropping the unused OLE relationship. The existing picture classifier still decides whether the preview is background: a decorative panel remains, while a sample screenshot is removed. [Two focused synthetic tests](../tests/test_ole_preview_adapter.py) and the existing background integration test passed. A read-only check found no OLE markup in the eight corpus files, so the fix does not alter their tested path. This is **not** evidence of real-world OLE compatibility.
