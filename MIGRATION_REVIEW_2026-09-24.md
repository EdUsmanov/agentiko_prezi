# Ревью двух веток: архетипы и подготовка PPTAgent

Дата: 24.09.2026. Это отчёт о проверенном этапе, не сертификат отсутствия
всех ошибок и не завершение миграции на PPTAgent.

## Короткий ответ про смысл решения

Идея разумная: повторно использовать реальные слайды пользователя, заранее
изучать шаблон и содержание, а затем собирать редактируемый результат.
Слабое место было в передаче смысла между стадиями, а не только в качестве
промпта или наличии OpenDesign.

Сам по себе переход на другую библиотеку не исправляет потерю фактов,
смешение назначения макета с его геометрией и отсутствие проверки результата.
PPTAgent полезен своим редактором реальных объектов и извлечением схемы макета.
Наши проверки исходных данных, модули шрифтов/цветов и семантические контракты
нужно сохранить вокруг него.

Целевая архитектура: один проверяемый сценарий и один выбранный исполнитель.
Не следует поддерживать два конкурирующих сценария, которые затем пытаются
исправлять друг друга, или называть собственный renderer полным PPTAgent.

## Исправлено в обеих ветках

- Каталог 19 межотраслевых архетипов с определениями и обязательными смысловыми
  слотами. Приложение — роль раздела, а не отдельный способ компоновки.
- Архетипы содержания подтверждаются цитатами исходных фактов, заголовков или
  связанных таблиц. Подставленные цитаты и чужие fact ID отклоняются.
- Процессы и сравнения сохраняются как целые смысловые блоки. Они не дробятся
  и не склеиваются только ради запрошенного числа слайдов.
- Слабые границы заголовков могут объединяться, если это названия сравниваемых
  объектов. Настоящие подтверждённые разделы сохраняются.
- Спикер может быть указан в заголовке. Название раздела само по себе не
  подтверждает наличие шага процесса.
- Одинаковые фразы в разных местах исходника больше не удаляются глобальной
  дедупликацией: у двух продуктов может быть одинаковая цена.
- Архетип сохраняется в сценах, подборе композиций и проверке разнообразия.
  Специализированные макеты больше не отсеиваются из-за принудительного content.
- Аудит замечает потерю архетипа и сообщает об использовании общего макета
  вместо специализированного.
- Библиотека примеров сохраняет назначение слайда, исключает служебные слайды
  и инвалидируется при изменении каталога, промптов или кода анализа.
- ZIP результатов формируется по явному списку публичных артефактов.
  Внутренние запросы, исходный generation-content и произвольные JSON не
  выдаются по совпадению расширения. Символические ссылки не публикуются.
- Упаковка исходников не обходит большие runtime-каталоги, сохраняет
  .dockerignore и создаёт отдельный архив для каждой рабочей копии.

## Экспериментальная ветка

OpenDesign исключён из контекста модели. Собственный экспорт дизайн-системы
сохранён. Скрипты коллег по шрифтам и цветам сохранены.

Docker Desktop 4.92.0 и Engine 29.8.0 установлены. Проверочный образ использует
upstream PPTAgent v0.2.0, commit d53296bc0ddd73e81d51c523d20dd711c7f233f3,
и необходимый ему закреплённый fork python-pptx. Зависимости основной .venv
не менялись ради upstream.

Наш редактор допускает только пять известных операций над слайдами, разбирает
их через AST и не исполняет Python модели через eval. Он изменяет копию слайда,
проверяет ссылки на изображения и явно завершается ошибкой после исчерпания
попыток. Контейнер остаётся дополнительной защитой парсеров и renderer.

Проверка на настоящем upstream прошла без сети и доступа к папкам Mac:
парсинг PPTX, замена текста, сохранение, повторное открытие редактируемого
текста и совместимость подкласса агента.

## Проверки

- Полный набор экспериментальной ветки после исправления публикации:
  320 passed, 1 skipped.
- Основная ветка после исправления публикации: 291 passed. Полный повтор
  вне песочницы прошёл; предыдущий прогон остановился на запрете ОС завершать
  группу дочерних процессов при shutdown, а не на проверке PPTX.
- Новый тест упаковки и три теста публикации: 4 passed.
- Проверки Chrome обеих веток: полный UI smoke, подтверждение нового числа
  слайдов, блокировка интерфейса при тестовой промпт-инъекции прошли.
- Реальный настроенный API обеих веток: speaker, comparison, process — 3/3
  в каждой ветке, без повторных попыток. Использовался синтетический текст.
- Проверочный контейнер PPTAgent: passed, full_generation_tested=false.

Unit/UI-тесты не доказывают визуальное качество презентаций.

## Существенные незавершённые части

1. Полный PPTAgent ещё не включён в UI. Экспериментальный UI явно это сообщает
   и запускает native baseline без OpenDesign, не маскируя его под v0.2.0.
2. Нужен защищённый bridge к модели: ключ хранится у доверенного приложения,
   worker не имеет сети и не выбирает endpoint или модель. Нужны лимиты
   запросов, размера сообщений, общего времени и проверка выходных файлов.
3. Полная привязка смысловых слотов к конкретным объектам макета ещё не
   реализована. Метка timeline сама по себе не создаёт корректный таймлайн.
4. Нужно проверить полный модельный цикл на нескольких реальных шаблонах,
   редактируемость таблиц/графиков, отсутствие старого текста и фактических
   искажений, разделители и результат после замечаний VLM.
5. SLA трёх презентаций за 300 секунд не подтверждён для полного PPTAgent.
   У upstream несколько модельных запросов на слайд; это существенный риск.
   Предварительный анализ можно кэшировать, но готовую генерацию нельзя
   незаметно переносить за пределы измеряемого этапа.
6. Полное визуальное A/B-сравнение движков ещё не проведено. Текущее сравнение
   двух запущенных UI не является доказательством преимущества PPTAgent.
7. Проверка в Р7-Офис/Astra Linux пока не выполнена.
8. Детектор промпт-инъекций не обеспечивает 100% распознавание. Основная
   защита — отсутствие полномочий у модели, изоляция и проверка действий.

## Что не делали

Не удаляли пользовательские задания, не переносили их между ветками,
не копировали ключ в исходники/архивы/контейнер и не переключали движок
автоматически при ошибке. Исходные локальные рабочие копии остаются на месте.
