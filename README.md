# VK Forma — Presentation Studio

Локальный прототип сервиса генерации презентаций в стиле пользовательского PPTX или POTX. Python 3.11+, FastAPI, нативные объекты PowerPoint, общий формат сцены для PPTX/HTML/PDF. Интерфейс на русском, без внешних CDN и сборки frontend.

## Что уже работает

- Анализ masters, layouts, обычных слайдов и вложенных групп; извлечение шрифтов, палитры, типографической шкалы, текстовых зон и повторяющихся небольших брендовых изображений.
- Необязательные демошаблоны: CLI регистрирует только исходные файлы. Анализируется лишь явно выбранный шаблон.
- Подготовка пользовательского шаблона, текста, Markdown-таблиц и ограничений в неизменяемый `PreparedPackage`.
- В API-режиме до таймера: смысловая классификация макетов по тексту/геометрии, анализ содержания и проверенный план. Отчёт `analysis.json` различает технический разбор, LLM-анализ, локальную отрисовку и не выполнявшуюся VLM-оценку. По требованию от 29.09.2026 добавлена явная команда предварительного анализа выбранных примеров. Пользовательский шаблон анализируется независимо; проверенные ответы сохраняются в собственном кэше. См. [анализ выбранного шаблона](REFERENCE_LIBRARY.md).
- Совпадающие раскладки LLM не отклоняют корректный план. Код назначает композиции и проверяет геометрию после исправлений; безопасное перестроение устраняет дубли. Если тесный шаблон не допускает различий, файлы сохраняются с `needs_review`, а не с ложным подтверждением разнообразия.
- Три варианта с одинаковым покрытием подготовленного содержания и проверкой разнообразия композиций; явно заданные «Слайд N» и порядок разделов сохраняются. Нативные текст, таблицы, столбчатые диаграммы из отдельных фигур.
- Перенос исходных фонов, графики masters/layouts и безопасного декора выбранного слайда; размещение нового текста в исходных зонах. Кэш графики для HTML готовится до таймера, новый текст остаётся живым DOM; PPTX сохраняет исходные нативные объекты.
- Два этапа: подготовка без конкурсного лимита; одна или три презентации и все экспорты за 300 секунд после явного клика «Создать» (требование от 29.09.2026). Для схемы 3 + 3 + 3 + 1 пользователь запускает четыре отдельных задания.
- Детерминированный аудит, ограниченное исправление вместимости таблиц, вывод замечаний. Ошибки итогового аудита блокируют публикацию файлов; `needs_review` означает доступный результат с предупреждениями или незавершёнными проверками.
- PPTX, живой HTML, PDF, PNG-предпросмотр, ZIP, manifest и история запусков.
- Интерфейс в палитре VK Tech: синий/чёрный/белый. Раздельные справочные сообщения и предупреждения, блокировка редактирования на время работы, восстановление наблюдения из истории, клавиатурный предпросмотр и мобильная навигация.
- Уточнение количества слайдов через чат создаёт новую версию подготовки. Свободные инструкции передаются модельному планировщику при его подключении.
- В новом API-конвейере нехватка слайдов для разделов и таблиц не обрывает анализ: сохраняется план с предупреждением «запрошено N, подготовлено M». Генерация увеличенного варианта требует подтверждения через кнопку с фактическим количеством (API: `accept_adjusted_slide_count`). Если нужно больше 30 слайдов, анализ сохраняется, но материал нужно сократить или разделить перед генерацией.
- OpenDesign: реальные vendored craft-файлы `typography.md` и `color.md` в контексте модельного планировщика; для каждого шаблона экспортируются `DESIGN.md` и tokens. Полный daemon OpenDesign не запускается.
- Устойчивость анализа: проверенные ответы кэшируются по версии пайплайна/входам/модели, проблемные группы макетов дробятся; непроверенные макеты исключаются. Разбор текста по 24 блока с повтором и сохранением исходного содержания при сбое. Частичный результат явно требует проверки, а отсутствие пригодного проверенного каталога остаётся блокирующей ошибкой. Подробности: [SEMANTIC_PIPELINE_V2.md](SEMANTIC_PIPELINE_V2.md).
- DeepPresenter v1.1.38: адаптированный upstream Design/Agent loop с выбором исходных композиций, обязательной проверкой и ограниченным числом итераций. Нативный renderer остаётся нашим. Это не полный upstream HTML/Research/VLM runtime; сравнение качества с версией коллег ещё не выполнено.
- Безопасный разбор ZIP/XML, изоляция подозрительных строк, запрет внешних активов, JSON-контракты, только три ограниченные операции композиции без shell/файлов/сети, CSP, происхождение фактов.

## Подготовленные шаблоны и четыре запуска

Схема сдачи от 29.09: VK Education → 3 презентации, VK WorkSpace → 3,
VK Tech → 3, Native American Heritage → 1. Каждый запуск пользователь начинает
отдельной кнопкой после анализа своего текста. Общий лимит одного задания —
300 секунд, включая проверку и упаковку файлов. Анализ текста и шаблона проходит
до этого таймера. Успешное завершение за лимит необходимо проверять на конкретном
объёме материала и оборудовании; установка таймаута сама по себе его не гарантирует.

Регистрация файлов и подготовка профилей выполняются явно:

```sh
python -m studio.cli index-examples education.pptx workspace.pptx tech.pptx heritage.potx --single-variant heritage.potx
python -m studio.cli preanalyze-examples
```

В API-режиме вторая команда использует настроенного провайдера модели и передаёт
ему данные шаблонов. Она не анализирует пользовательский текст и не создаёт
готовые презентации. Штатный анализ, отчёты и происхождение запросов сохраняются
в `data/references/`, проверенный кэш — в `data/template-cache/`. Выбор шаблона
показывает готовый профиль; кнопка генерации остаётся выключенной до анализа текста.
При изменении файла, зависимостей анализа, настроек модели или шрифтов устаревший
кэш не выдаётся за готовый. Каталог `data/` локальный и не переносится через git push.
У новых пакетов нет автозапуска. Старые готовые результаты остаются доступны.

## Быстрый запуск без модели

Установите Python 3.11+ и выполните из терминала:

```bash
git clone https://github.com/EdUsmanov/agentiko_prezi.git
cd agentiko_prezi
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m studio.cli serve --port 8765
```

Откройте `http://127.0.0.1:8765`. Загрузите PPTX/POTX, добавьте свой текст или демотекст, проанализируйте материалы и выберите генерацию одной либо трёх презентаций. Для новой презентации на основе изученного шаблона откройте контекстное меню записи в истории.

Для проверки интерфейса без реального конвейера запустите `python -m studio.mock_app --port 8765`. Мок подменяет только ответы API; оба режима отдают один и тот же фронтенд из `web/`.

Для встроенных сжатых EOT/MTX-шрифтов нужен Node.js в PATH либо
`STUDIO_NODE_EXECUTABLE=/absolute/path/to/node`. npm-пакеты устанавливать не нужно:
декодер включён в исходники. Если Node отсутствует, остальные форматы шрифтов
и разрешённый поиск точного открытого начертания продолжают работать. См. FONTS.md.

POTX поддерживается при загрузке, повторном анализе и CLI-индексировании, в том числе без демонстрационных слайдов, только с masters/layouts. Тип определяется по содержимому OOXML: для библиотеки меняется только декларация template→presentation в копии в памяти. Исходные байты и SHA-256 сохраняются; внутреннее имя `input.pptx` историческое и не означает конвертацию исходника. На выходе всегда обычный редактируемый PPTX, а не переименованный POTX. Макросы (POTM/PPTM), старый бинарный POT и защищённые файлы не поддерживаются. Ограничения сложных макетов и шрифтов остаются общими для обоих форматов.

Для PDF/PNG из готового PPTX нужен LibreOffice (`soffice` в PATH либо `STUDIO_SOFFICE=/absolute/path/to/soffice`). На текущем Mac обнаруживается также bundled runtime. Каждый процесс использует отдельный профиль и каталог шрифтов документа через Fontconfig; системные шрифты не устанавливаются. Без LibreOffice сохраняется резервный экспорт сцены, но результат помечается `needs_review`. После обновления повторно проанализируйте шаблон: ранее подготовленные пакеты не меняются автоматически.

Windows: для воспроизводимого запуска используйте WSL2 (Ubuntu) и команды Linux из TEAM_SETUP.md. Нативный Windows пока не проверен: управление дочерними процессами использует POSIX process groups. Интерфейс предназначен для настольных браузеров. В этой среде проверен Chromium, полная матрица Chrome/Firefox/Safari/Яндекс на Windows/macOS ещё не пройдена.

Необязательная регистрация демопримеров без анализа и LLM-вызовов (самих файлов в Git нет):

```bash
python -m studio.cli index-examples "/path/education.pptx" "/path/workspace.pptx" "/path/tech.pptx"
```

Можно загрузить неизвестный шаблон через интерфейс. Анализируется только он; другие примеры не обрабатываются и не влияют на генерацию.

## Режимы модели

По умолчанию `STUDIO_MODEL_MODE=extractive`: workflow работает без сети и ключей, но не заменяет LLM/VLM. В обоих режимах используется один сценарий с подтверждёнными фактами. Автоматическое расширение короткого материала проектными тезисами отключено. Изменение числа слайдов требует подтверждения пользователя; сравнения и процессы не дробятся только ради заданного числа.

При анализе настроенный inference provider получает текст, параметры макетов и изображения слайдов для определения назначения шаблона. При визуальной проверке передаются рендеры готовых слайдов, содержащие в том числе загруженные пользователем картинки, и очищенные образцы фирменной графики. Исходный файл PPTX провайдеру не отправляется. Нужна модель с поддержкой изображений; невыполненная VL-проверка не считается успешной.

Для подключения разрешённой модели создайте `.env` по `.env.example` и задайте endpoint совместимого chat-completions API. Наличие совместимого HTTP-протокола не означает использование моделей OpenAI. Ключ читается только сервером и не сохраняется в manifest.

```dotenv
STUDIO_MODEL_MODE=api
STUDIO_MODEL_BASE_URL=https://your-provider.example/v1
STUDIO_MODEL_ID=your-open-weight-model
STUDIO_MODEL_API_KEY=replace-locally
STUDIO_MODEL_PARAMETERS_B=32
STUDIO_MODEL_OPEN_WEIGHTS=true
STUDIO_MODEL_LICENSE=Apache-2.0
STUDIO_STAGE=selection
```

Перезапустите сервер. Для финала задайте `STUDIO_STAGE=final` и точный hostname VK endpoint в `STUDIO_VK_ALLOWED_HOSTS`. В финальном режиме автономный запуск запрещён. Метаданные модели подтверждает оператор, а не приложение; сверка model card и лицензии остаётся обязательной при подключении.

Поддержаны также имена `LLM_API_KEY`, `LLM_CHAT_COMPLETIONS_URL` (полный URL с `/chat/completions`) и `LLM_MODEL`. Непустые `STUDIO_MODEL_*` имеют приоритет. Сами credentials не включают API-режим и не отменяют проверку модели.

Текущая командная конфигурация использует OpenRouter, `qwen/qwen3.8-27b`, провайдера Alibaba без fallback, `STUDIO_MODEL_THINKING=false` и `STUDIO_MODEL_STRUCTURED_OUTPUT=false`. В запросах OpenRouter reasoning выключен, используется JSON mode; структура ответа дополнительно проверяется сервером. Конфигурация для коллег находится в `.env.team`, её нужно скопировать в локальный `.env`. Другие провайдеры и прошлые результаты NeuralDeep описаны в исторических отчётах; это не текущие настройки запуска.

Невыполненная дополнительная проверка может дать `needs_review`. Сбой обязательного анализа или Design останавливает задание. Ошибки финального аудита запрещают публикацию: наличие технически созданного файла не означает доступный результат.

OCR: добавлен отдельный транспортный адаптер, пока без включения в интерфейс и конкурсную генерацию. Контракт, ограничения и условия включения описаны в [OCR.md](OCR.md).

## Движок генерации

В API-режиме по умолчанию используется `STUDIO_ENGINE=deeppresenter`; автономный режим выбирает `native`. Для явного возврата к прежнему собственному движку задайте `STUDIO_ENGINE=native` и перезапустите сервер. Это не старый сторонний PPTAgent: его небезопасный executor не подключён, необходимости в нём сейчас нет.

Минимальные зависимости нового runtime входят в `requirements.lock`; при установке editable-пакета: `python -m pip install -e '.[deeppresenter]'`. Docker, upstream CLI/onboard и модельный shell не нужны. OpenAI SDK используется только для типов сообщений; inference по-прежнему идёт через наш HTTP gateway к разрешённой модели.

На выбор композиций — до 6 ходов; сетевые запросы имеют отдельные тайм-ауты и ограничены оставшимся временем общего 300-секундного бюджета генерации. Модель может выбрать только существующие pattern IDs или явный token:auto для всех слайдов; не меняет факты, шрифты, цвета или файлы. После изменения плана нужна повторная проверка. При ошибке новый runtime не подменяется старым молча: запуск завершается с ошибкой. Версия, операции и тайминги отражаются в manifest. Детали: [PPTAGENT_INTEGRATION.md](PPTAGENT_INTEGRATION.md).

## Шрифты

Сначала используется шрифт, встроенный в пользовательский PPTX: статический TrueType или поддерживаемый несжатый EOT. Он хранится только в задании и сохраняется в итоговом PPTX. Затем проверяется точное локальное начертание. Включены открытые Play Regular и Montserrat Regular/Medium/Bold с лицензиями в `fonts/`. Можно добавить законно доступный TTF в `fonts/` без перезапуска сервиса.

Название шрифта не гарантирует наличие полного файла или нужного алфавита. Недоступное точное начертание сначала ищется в системе и загружается из разрешённых каталогов. Если его нет, для экспорта выбирается доступное начертание того же семейства, основной шрифт шаблона или поставляемый Montserrat. При недостаточном покрытии нового текста также применяется автоматическая замена, в том числе для кириллицы. Предупреждение и фактически использованные шрифты сохраняются в отчёте. Правила встраивания и лицензий — [FONTS.md](FONTS.md).

## Границы текущей версии

- Текстовый LLM и адаптированный DeepPresenter проверены через настроенный endpoint; это не подтверждает VLM или качество полного upstream. Экстрактивный прогон не является доказательством скорости модели.
- PDF и PNG отрисовываются из самого PPTX через LibreOffice. Добавлена отдельная визуальная проверка этих PNG через модель с поддержкой изображений: `STUDIO_VLM_ENABLED=true`. Включать только после разрешения на передачу изображений настроенному провайдеру. По умолчанию выключена. Неполная/отключённая проверка в API-режиме даёт needs_review, а не визуальное одобрение. OCR не подключён.

### Вёрстка и визуальная проверка (parser v5)

Списки и выделенные начала пунктов сохраняются при разборе Markdown; PPTX использует редактируемые native bullets, HTML — списки. Поддерживаются титульные макеты, до шести body-зон, парные заголовки и номерные позиции. Заголовки ограничиваются фактической плашкой, аудит проверяет попадание текста в исходный контейнер. Безопасная графика выбранного макета сохраняется; произвольные фотографии/библиотека иконок не копируются без семантического соответствия.

Пакеты анализа до v5 необходимо проанализировать заново. Сохранённые результаты продолжают открываться.

VLM получает до 4 PNG в запросе и проверяет все слайды всех вариантов в общем бюджете генерации. При HTTP 400/413 пакет уменьшается вплоть до одного PNG без сброса бюджета; ошибки авторизации не повторяются. Отчёт содержит подтверждённые моделью номера и хеши отправленных изображений. Ошибки и неполное покрытие не выдаются за успешную проверку. Это отдельный визуальный critic Studio, не полный upstream DeepPresenter visual reflection. Подробности доступны в журнале и отчёте; модель не исполняет произвольный исправляющий код. Передача пользовательских PNG требует отдельного разрешения. Даже завершённая VL-проверка может пропустить дефект и не заменяет геометрический аудит.
- Сложные picture-driven макеты, SmartArt и семантика всех объектов произвольного примера не поддерживаются полностью. Старый текст и непроверенные фотографии/диаграммы не копируются в новые слайды. Текстовые надписи в masters/layouts очищаются, в том числе текстовые логотипы; логотипы в фоновых изображениях и графике сохраняются. При отсутствии безопасного паттерна token composition явно помечается требующей проверки.
- Доработка поддерживается через новый запуск с новыми ограничениями. Точечное редактирование произвольного объекта существующей презентации не реализовано.
- Генерация изображений для финала не реализована; есть зафиксированное расширение в требованиях. SmartArt необязателен согласно Q&A.
- Материал не обрезается молча. Переполнение текста допускает адресную редактуру с сохранением источников. Таблицы, графики и пересечения сначала требуют исправления компоновки. Если допустимого решения нет, подготовка останавливается с диагностикой; данные не удаляются ради успешного статуса. См. [маршрутизацию исправлений](REPAIR_ROUTING.md).
- Это single-user localhost-приложение. Аутентификация, tenant isolation и публичное размещение не входят в реализованный контур. Сервер по умолчанию слушает только loopback.
- Неограниченное время подготовки не означает неограниченный размер загрузки: действуют защитные лимиты файлов и объектов.

Текущее поведение описывают README, [ARCHITECTURE.md](ARCHITECTURE.md), [REPAIR_ROUTING.md](REPAIR_ROUTING.md) и [TEAM_SETUP.md](TEAM_SETUP.md). Датированные аудиты и handoff-пакеты — исторические снимки, а не инструкции к текущему запуску.

# Шрифты

Подготовка использует поставляемый набор `font-extraction-kit (1)`: он создаёт `font-model.json` версии 2 и точные файлы начертаний для ролей слайдов. Если точный файл отсутствует, включённый поиск сначала пытается загрузить его, затем адаптер явно подставляет доступный шрифт и сообщает об отличии от шаблона. TTF/OTF можно добавить в `fonts/` или `data/local-fonts/` для точного воспроизведения.

При `STUDIO_DOWNLOAD_FONTS=true` набор ищет отсутствующие варианты в Google Fonts, Fontsource и официальном пакете Aptos. Для встроенных EOT/MTX требуется Node.js 24. Подробнее о модели, правах на шрифты и ограничениях экспорта: [FONTS.md](FONTS.md).

## Иллюстрации и защита от инъекций — 24.09.2026

В форму добавлена загрузка до 12 PNG/JPEG/WebP (8 МБ на файл, 24 МБ суммарно). Прикреплённая картинка ссылается на раздел через `![Подпись](имя-файла.png)`; без ссылок файлы распределяются автоматически. Каждый файл вставляется один раз в каждый вариант, до четырёх на слайде, без искажения пропорций. Изображения сохраняются при правках. Ссылки на удалённые картинки не загружаются.

Метаданные удаляются, файл декодируется и заново сохраняется в PNG, hash проверяется перед генерацией. Пиксели не передаются планировщику: команды на картинке остаются содержимым, а не действием. Финальная VL-проверка видит их как часть слайдов, но может только сформировать замечания, не выполнять команды или отменять кодовые проверки. OCR-детектор инъекций не заявляется. Подробности и ограничения: [IMAGE_SECURITY.md](IMAGE_SECURITY.md).
