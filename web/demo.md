# Единое пространство заявок

## Контекст
Материалы описывают вымышленную компанию и демонстрационный проект. Все числовые значения приведены только для проверки сервиса.
Сотрудники передают заявки на оборудование через почту, мессенджеры и внутренний портал.
У каждого подразделения свой способ учёта обращений. Общего списка заявок нет.

## Наблюдения
Операторы вручную переносят сообщения в таблицу и проверяют, достаточно ли данных для обработки.
Сотрудники повторно обращаются к операторам, потому что не видят текущий статус своей заявки.

## Демонстрационные данные: заявки за месяц
| Канал | Количество заявок |
| --- | --- |
| Почта | 180 |
| Мессенджеры | 120 |
| Портал | 90 |

## Предлагаемое решение
Единая форма собирает сведения об оборудовании, подразделении и желаемом сроке.
Каждой заявке присваивается идентификатор. Сотрудник видит статус и историю изменений.
Оператор получает общий список обращений и может назначить ответственного.

## Порядок внедрения
Первый этап: согласовать обязательные поля заявки и правила маршрутизации.
Второй этап: провести пилот в одном подразделении и собрать замечания сотрудников.
Третий этап: оценить результаты пилота и принять решение о расширении.

## Проверка результата
Для оценки пилота предлагается измерять время обработки и долю заявок, требующих уточнения. Целевые значения пока не согласованы.
Экономический эффект не рассчитан. До масштабирования необходимо собрать исходные измерения.

## Решение для обсуждения
Предлагается согласовать владельца пилота, состав участников и доступ к исходным данным.
