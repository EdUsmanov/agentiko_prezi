# Контракты этапов и зависимости модулей

Обновлено 27.09.2026. Публичные точки входа остаются `pipeline.prepare`, `pipeline.load_package` и `pipeline.generate`. API и формат сохранённого `PreparedPackage` не менялись.

## Подготовка

`pipeline.prepare` создаёт `PreparationRequest` и передаёт зависимости через `PreparationServices`. Модуль `preparation.py` последовательно выполняет:

1. `prepare_template` — проверка входа, технический анализ или кэш; результат `TemplatePreparation`. При нехватке шрифтов сохраняется прежний статус `waiting_fonts` и материал для продолжения.
2. `prepare_materials` — исходный материал, ограничения, шрифты, изображения и контрольные суммы; результат `PreparedPackage`.
3. Модельная подготовка — через переданную `prepare_intelligence`; gateway закрывается в `finally`.
4. `check_prepared_package` — проверка шрифтов после модельных изменений, композиций и диагностик.
5. `seal_preparation` — запись JSON, хэша и статуса `ready`. Ошибки отдельно сохраняет `record_preparation_failure`.

Зависимости передаются явно, без обратного импорта `pipeline` из нижних модулей. Старые тесты и интеграции могут по-прежнему подменять фабрику gateway и анализатор в публичном фасаде.

## Генерация

`generation.run_generation` управляет порядком стадий и прогрессом. Контракты определены в `stage_results.py`.

| Этап | Модуль | Результат |
|---|---|---|
| Подготовленный план или планировщик, затем выбранный движок | `generation_planning.py` | `PlanningResult`, `EngineReport` |
| Композиция и локальные исправления | `generation_composition.py` | `CompositionResult`, `DiversityResult` |
| Параллельный экспорт вариантов | `generation_composition.py` | `list[VariantResult]`, внутри `RenderingResult` |
| Проверка фактического текста и изображений, ограниченное исправление | `generation_reviews.py` | `ReviewedGeneration`, `ContentReviewResult`, `VisualReviewResult`, `RefinementReport` |
| Повторный аудит окончательных файлов | `generation_audit.py` | `FinalAuditResult`, `SemanticBinding` |
| Отчёт, контроль публикации и архивы | `generation_publication.py` | Существующие manifest и состояние задания |

Объекты результатов читаются через атрибуты. На границах существующих проверяющих компонентов и JSON используется явное преобразование `model_validate` / `wire()`. Неизвестные поля, неверные статусы, строка вместо флага и неверные числовые ограничения отклоняются. Завершённая визуальная проверка должна покрывать все слайды; принятое исправление должно иметь статус `completed` и явный список разрешённых `LayoutEdit`.

`ReviewedGeneration` проверяет соответствие порядка, ключей и числа слайдов между планами, сценами и экспортами. `export_findings` передаются циклу исправления как промежуточные доказательства. В итоговый JSON они отдельно не попадают: перед публикацией фактический экспорт проверяется заново, замечания добавляются к финальным `findings`.

Один `GenerationDeadline` сохраняет общий бюджет и резерв для экспорта. При `deadline_at=null` общий лимит отсутствует. Отчёт сохраняется до контрольной проверки для диагностики отказа; архивы создаются только после `require_publishable`. Итоговый статус выставляется после упаковки и повторной проверки времени.

## Направление зависимостей

Общие схемы и чистые функции вынесены в отдельные модули:

- `editorial_domain`, `narrative_data`, `layout_edits` — схемы, проверка доказательности и разрешённые операции.
- `narrative_layout`, `section_metadata`, `slide_budget` — сценарий, членство разделов и согласование количества.
- `content_sources`, `content_syntax`, `review_grounding` — источники фактов, синтаксис и привязка замечаний к реальным слайдам.
- `text_composer`, `pptx_text` — текстовые элементы и запись текста OOXML.
- `template_geometry`, `shape_geometry`, `native_surface` — цвета, геометрия и безопасное копирование исходной графики.
- `scene_regions`, `scene_quality` — занятость зон и абсолютные проверки качества без выбора новых композиций.

Прежние публичные импорты сохранены явными реэкспортами. Внутренний потребитель должен импортировать функцию из её владельца, а не из старого фасада. Тест `test_studio_module_dependencies_are_acyclic_including_local_imports` проверяет весь граф собственных модулей верхнего уровня `studio`, включая импорты внутри функций. Vendored пакеты не входят в эту гарантию.

Перемещённые зависимости включены в версии соответствующих кэшей. Изменение проверки должно инвалидировать её старые результаты, даже когда код проверки теперь находится в новом файле.

## Совместимость и границы

`wire()` сохраняет отсутствующие необязательные поля отсутствующими. Формат `package.json`, версия его схемы и неизвестные исторические диагностические поля сохраняются. Хэш проверяется по исходным байтам файла до разбора; пересериализация не используется для обхода проверки целостности.

Это типизация границ основных этапов, а не каждого словаря проекта. Внутренние диагностические данные `PreparedPackage.analysis`, часть форматов запросов и реализаций старых проверок остаются JSON-структурами. Расширяемые события, данные полей шаблона и сведения о замене шрифтов ограничены типом `JsonValue`. Полная статическая проверка типов всего проекта пока не включена.

Крупные специализированные функции композиции и детальной редакторской валидации остаются отдельными кандидатами на дальнейшее разделение. Текущий рефакторинг выделяет оркестрацию анализа/генерации, подготовку визуальных доказательств и выбор исправлений; он не меняет правила под конкретные шаблоны и не подтверждает ручную приёмку дизайна.
