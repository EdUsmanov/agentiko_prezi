# VK Forma: установка и запуск для команды

## 1. Доступ к репозиторию

Владелец приглашает коллег через GitHub → Settings → Collaborators → Add people. Для разработки нужен доступ Write. После принятия приглашения клонируйте приватный репозиторий через GitHub Desktop или терминал:

```bash
git clone https://github.com/EdUsmanov/agentiko_prezi.git
cd agentiko_prezi
```

Если Git запрашивает авторизацию, используйте GitHub Desktop, GitHub CLI (`gh auth login`) или настроенный credential manager. Пароль от аккаунта GitHub для Git по HTTPS не подходит.

## 2. Системные зависимости

- **Python 3.12+** с `venv` и `pip`; для воспроизведения текущей версии рекомендуется Python 3.12.
- **LibreOffice** нужен для отрисовки реальных PPTX в PDF и PNG. На macOS приложение в `/Applications/LibreOffice.app` находится автоматически; на Linux `soffice` должен быть в PATH.
- **Node.js** нужен для декодирования сжатых встроенных шрифтов EOT/MTX. npm-пакеты и сборка фронтенда не нужны.
- **Git** для получения кода и совместной работы.

На macOS при установленном Homebrew:

```bash
brew install python@3.12 node
brew install --cask libreoffice
```

На Ubuntu с Python 3.12+:

```bash
sudo apt-get update
sudo apt-get install python3-venv python3-pip libreoffice-impress nodejs git
```

Локально проверена macOS. На Windows рекомендуется WSL2 с Ubuntu: нативный Windows пока не проверен, управление процессами использует POSIX API. Отсутствие LibreOffice или нужного шрифта влияет на качество результата, а не только на предпросмотр. Коммерческие шрифты и пользовательские шаблоны в репозиторий не включены.

## 3. Python-окружение

Все команды выполняются из папки `agentiko_prezi`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.lock
```

Если установлено несколько Python, используйте `python3.12 -m venv .venv`. Фиксированные версии Python-зависимостей находятся в `requirements.lock`. Установка пакетов коллег отдельно не нужна: используемые модули входят в `studio/_vendor/`.

## 4. Конфигурация модели

Для работы с общей командной моделью:

```bash
cp .env.team .env
```

Если `.env` уже существует, сначала сохраните свои настройки: команда копирования перезапишет файл.

По решению владельца в **приватный** репозиторий включён общий командный ключ OpenRouter в `.env.team`. Использование оплачивается общим аккаунтом. Локальный `.env` игнорируется Git. Перед публичным распространением потребуется удалить ключ из всей истории и отозвать его у провайдера; простого удаления файла недостаточно. ZIP исходников, создаваемый `scripts/package_source.py`, командный ключ не содержит.

Текущий режим: API, движок DeepPresenter, `qwen/qwen3.8-27b`, Alibaba, без fallback и thinking. Визуальные проверки включены: текст и изображения слайдов передаются настроенному провайдеру. Переменные окружения процесса имеют приоритет над `.env`; после изменения настроек перезапустите сервер.

Для локальной проверки без LLM используйте `.env.example` вместо `.env.team`:

```bash
cp .env.example .env
```

Это ограниченный extractive-режим, он не воспроизводит качество модельного анализа. Для полностью автономного запуска дополнительно задайте `STUDIO_DOWNLOAD_FONTS=false`.

Если LibreOffice или Node не находятся автоматически, задайте в `.env` полный путь:

```dotenv
STUDIO_SOFFICE=/absolute/path/to/soffice
STUDIO_NODE_EXECUTABLE=/absolute/path/to/node
```

## 5. Запуск приложения

```bash
source .venv/bin/activate
python -m studio.cli serve --port 8765
```

Откройте **http://127.0.0.1:8765**. API-документация: http://127.0.0.1:8765/docs.
Сервер работает, пока открыт терминал; остановка — Ctrl+C. При занятом порте используйте, например, `--port 8766`.

Выберите свой PPTX/POTX: анализ шаблона начнётся сразу, пока вы вводите текст и ограничения. После отправки материалов система предложит структуру и количество слайдов. Можно принять план или запросить изменение; при отсутствии действий в течение 60 секунд запускается генерация трёх вариантов. Результаты доступны в интерфейсе и сохраняются локально в `data/v2/`. Каталог задаётся через `STUDIO_DATA_DIR`; каждый отдельный экземпляр должен использовать свой каталог. Прежние файлы из `data/` не удаляются, автоматической миграции истории нет.

Исходные шаблоны, история запусков и результаты другого разработчика не появятся после клонирования: они намеренно исключены из Git. Для недостающих шрифтов загрузите доступные вам точные начертания согласно подсказкам приложения и [FONTS.md](FONTS.md). Статус `needs_review` означает, что файлы требуют проверки; скачивание результата не подтверждает его визуальное качество.

Приложение рассчитано на отдельный localhost-сервер у каждого коллеги. Аутентификация и изоляция нескольких пользователей для общего публичного сервера пока не реализованы.

## 6. Тесты и обновление

```bash
python -m pip install -r requirements-dev.txt -r requirements-e2e.txt
python -m playwright install chromium
# На Linux для установки системных библиотек браузера:
# python -m playwright install --with-deps chromium
ruff format --check studio tests scripts test_support e2e
ruff check studio tests scripts test_support e2e
node scripts/ui_phase_labels_test.cjs
python -m pytest -q
python -m pytest -q e2e
```

Браузерные тесты сами запускают отдельный сервер и локальный replay провайдера; предварительно запускать приложение, копировать `.env.team` или оплачивать модельные запросы не нужно. Playwright нужен только для тестов. Шаблоны и ответы синтетические; эта проверка не заменяет ручной прогон с реальной моделью. Подробности и разбор сбоев — [TESTING.md](TESTING.md).

Для обновления остановите приложение и сохраните согласованные изменения в `main`, затем:

```bash
git switch main
git pull --ff-only
python -m pip install -r requirements.lock
python -m studio.cli serve --port 8765
```

После обновления пайплайна повторно проанализируйте материалы. Сохранённые результаты остаются в `data/v2/`. Правила совместной работы в `main` — в [CONTRIBUTING.md](CONTRIBUTING.md).
