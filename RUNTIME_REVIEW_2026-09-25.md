# Ревью двух движков — 25.09.2026

## Архитектура и исправления

Один подтверждённый сценарий задаёт заголовки, факты, разделы и архетипы для
трёх визуальных вариантов. Движки выбирают оформление, не пишут вторую версию
содержания. Автоматическое дополнение короткого материала неподтверждёнными
тезисами отключено; изменение количества слайдов требует подтверждения.

- Основная ветка: DeepPresenter выбирает композиции, штатный exporter строит PPTX.
- Эксперимент: настоящий PPTAgent v0.2.0 (commit
  d53296bc0ddd73e81d51c523d20dd711c7f233f3) разбирает шаблон, выбирает макеты,
  вызывает coder и редактирует реальные объекты. OpenDesign здесь не используется.
- Схема полей извлекается из объектов, а не угадывается отдельным LLM-запросом.
  Текст контракта привязан к ID объекта. Перестановка участников сравнения
  не проходит проверку даже при сохранении всех слов на слайде.
- Добавлены безопасные области для пользовательских изображений, редактируемых
  таблиц и диаграмм. Проверяются ячейки, числа, изображения и фактический текст.
- Непривязанные образцовые надписи получают явный контракт очистки.
- Исправлены потеря короткого подзаголовка, пропуск карточных макетов с 4+
  полями, попадание текста в вертикальную раскладку и перенос целых слов заголовка.
- Геометрическая проверка читает готовые PPTX. Допускается ограниченное уменьшение
  шрифта внутри исходного объекта; фоновые карточки не растягиваются.
- Замечания проходят ограниченный цикл исправления и повторной проверки.
  Публикация исправлений заменяет целые папки, не оставляет старые PNG и
  откатывает все замены при ошибке. Ошибка отката останавливает публикацию.
- VL-проверка получает настоящий рендер LibreOffice. Образец с прежним текстом
  заменён очищенной графикой макета: в первом A/B модель ошибочно приписывала
  CSS-код из референса результату, хотя его не было в готовом слайде.
- Отбор реальных слайдов и вместимость полей проверяются до ограничения списка
  кандидатов. Процесс с картинкой больше не теряет рабочие макеты из-за
  преждевременного предпочтения трёх колонок или маленького picture-placeholder.
- Общая композиция не наследует графику случайного титульного layout.
  Регрессионный рендер подтвердил устранение куба поверх текста на слайде процесса.
- PPTAgent хранит контракт текущего слайда в контексте его async-задачи.
  Одинаковые заголовки и текст разных слайдов не смешивают их поля.
- Различия вариантов измеряются по геометрии содержимого экспортированных PPTX.
  Разные ID, подписи и цвета сами по себе не считаются разными композициями.

## Шрифты

В ошибочном основном запуске a90b4c3628454206b0506d7c7fb291b0 не хватало U+2192.
Его нет и в полном Play Regular, а не только во встроенном подмножестве.
Добавлена ограниченная подстановка Montserrat для отсутствующих стрелок/маркеров;
обычные буквы остаются в исходном начертании. Одна и та же сегментация используется
для измерения и отображения. Неизвестные буквы/эмодзи не подменяются молча.
Старый content_archetypes ValueError больше не приписывается позднему сбою шрифта.

Montserrat поставляется в исходном архиве с OFL. Новые fallback-runs ссылаются
на это начертание; универсальное встраивание нового TTF во все PPTX не заявляется.
Для одинакового отображения на другом компьютере нужен этот шрифт.

Пользователь явно разрешил точечный fallback с предупреждением. Это осознанное
исключение из строгого конкурсного правила «только шрифты шаблона», а не
утверждение о полном соответствии этому пункту ТЗ.
Предупреждение показано при анализе; фактические подстановки из готового PPTX
записаны в font_substitutions и warnings результата/manifest. Пути шрифтов
в этом отчёте не публикуются.

## Библиотека

Все три примера анализируются при изменении fingerprint пайплайна. Новая версия
публикуется целиком; прежняя сохраняется. Непроверенные макеты исключаются.
Частичный разбор допускается только при наличии проверенных рабочих макетов и
показывается предупреждением. Полностью неразобранный пример не считается готовым.
Совпадающий по SHA пользовательский шаблон использует проверенную семантику
библиотеки; новый текст всегда анализируется отдельно.

## Итог оптимизации модельного coder

Финальный контрольный VK Tech: job 527417d9f76a4ebfb0a3419524870bb4,
3 × 7 слайдов за 274,284 с вместе с экспортом, проверками и одной попыткой
исправления. Все 21 начальных вызова coder завершились успешно, наибольшее
время ответа — 19,858 с. В этом запуске сетевой retry не понадобился.
Короткие запросы coder и исправление очереди устранили прежний тайм-аут
именно на этом сценарии. Это не гарантия SLA на всех шаблонах/30 слайдах.

VL проверила 21/21 слайд; контекстный критик завершился без замечаний.
Геометрически различны 3 варианта. Однако результат — needs_review, ошибок
в отчёте 22: три table_coverage, шестнадцать метрических переполнений ячеек,
три визуальных ошибки переполнения/переноса. Есть дополнительные визуальные
предупреждения. При ручном просмотре подтверждены неудачное размещение текста
поверх декора и заголовок таблицы с переносом внутри слова.
Попытка ремонта отклонена как не подтвердившая улучшение; исходные результаты
не заменены худшими. Поэтому миграция и качество готового продукта НЕ закрыты.

Это изолированный прогон движка с заранее подтверждённым синтетическим
сценарием, свежим выбором макетов и настоящим модельным coder, а не новый
сквозной HTTP A/B. В UI работает та же реализация на порту 8766, но библиотека
после последнего изменения пересобирается, и полный новый HTTP A/B ещё нужен.
Оставшийся технический блокер — достаточная вместимость областей таблиц и
текста с учётом декора, а не скорость или отсутствие подключения coder.

## Вывод по смыслу решения

Связка «подтверждённые факты → семантические поля → реальные объекты → проверка»
обоснована. Два независимых автора и подсчёт source_ids вместо чтения PPTX были
ошибочным направлением; они устранены. Слабое место остаётся в качестве разбора
произвольного шаблона и вместимости его объектов, не в количестве агентов.

Не заявляются: полная специализированная вёрстка всех 19 типов, поддержка
POTX без слайдов-образцов экспериментальным движком, универсальная сохранность
SmartArt/сложных групп, гарантия отсутствия визуальных ошибок, проверка Р7/Astra.
Docker без сети, ключей и host mounts; только ограниченные AST-команды редактора.
Данные веток раздельны; разрешённые настройки модели читаются из основной .env
в память. Код шрифтов/цветов коллег сохранён.
