# Изображения и границы доверия

## Пользовательский сценарий

Загрузите текст, PPTX/POTX и до 12 картинок PNG, JPEG или WebP в поле «Иллюстрации к материалу». Каждая картинка — не более 8 МБ и 20 миллионов пикселей; все картинки вместе — не более 24 МБ. Анимация, SVG, PDF под видом картинки и неизвестные форматы отклоняются. Изображения уменьшаются до 2400 px по длинной стороне, поворот EXIF применяется, затем записывается новый PNG только из пикселей, без EXIF/XMP/ICC/текстовых комментариев.

Чтобы привязать изображение к разделу Markdown:

```markdown
## Процесс согласования
Заявки проходят проверку и поступают ответственному сотруднику.
![Схема процесса](process.png)
```

Прикрепите `process.png` отдельным файлом. Используется точное имя без папок; ссылки HTTP, file и data не загружаются. Неизвестное локальное имя вызывает понятную ошибку. Повторная ссылка на одну картинку пока не поддерживается. Без Markdown-ссылки картинки равномерно распределяются по слайдам в порядке загрузки.

Каждый файл размещается один раз **в каждом из трёх вариантов**; до четырёх изображений на слайде. Когда картинок слишком много для заданного числа слайдов/раздела, подготовка просит увеличить число слайдов, а не теряет вложения. Изображения вписываются с сохранением пропорций без обрезки в отдельную область исходного контейнера; текст и таблицы остаются отдельными редактируемыми объектами. Возможное переполнение текста фиксируется аудитом. Подпись Markdown сохраняется как альтернативный текст картинки; автоматически рисуемых подписей под изображениями пока нет.

Привязка основана на разделе Markdown, **не на семантическом распознавании картинки**. OCR и визуальное понимание новых вложений на этапе планирования не включены. Картинку нельзя использовать как единственный источник текста/чисел презентации: исходные факты по-прежнему нужны текстом.

## Защита от промпт-инъекций

### Блокирующий экран и остановка запроса

При обнаружении известной сигнатуры новый запрос отклоняется, а не продолжает
работу с очищенным текстом. Проверяются исходный текст, аудитория, пожелания,
имена вложений; в PPTX/POTX — текст параграфов (включая таблицы, заметки,
masters/layouts) с объединением runs и названия/описания объектов.
Проверка выполняется до анализа шрифтов, отрисовки и обращений к модели.
Повторная генерация старого пакета с карантином также запрещается.

API возвращает код `prompt_injection_detected`, асинхронное задание —
`security_violation` и состояние `failed`. Исходная инструкция не выводится
в сообщении ошибки. Интерфейс показывает полноэкранное модальное изображение,
блокирует фон, фокус и запись через клиентский API, запрещает Escape.
Блокировка сохраняется в sessionStorage данной вкладки после перезагрузки.
Кнопка очистки сбрасывает только текущий ввод и выбранные файлы, не историю.
Это не блокировка пользователя/всего сервера: другие вкладки и пользователи
не наказываются за чужой документ. Сервер независимо отклоняет опасный запрос,
поэтому удаление оверлея в DevTools не разрешает его выполнение.

Низкоуровневый `scan_text` по-прежнему умеет карантинировать строки для отчёта;
теперь admission gate останавливает пользовательское задание целиком. Правила
остаются эвристическими, возможны ложные срабатывания. OCR-детектор в пикселях
не добавлялся. Картинка блокировки — предоставленный пользователем локальный
JPEG; её показ не требует обращения к внешнему хосту.

1. Исходный текст, имя шаблона, подписи и модельные ответы не становятся системным промптом. В gateway общий системный барьер явно относит текст, пиксели, QR-коды и надписи к недоверенным данным. Нет model tools, shell, кода, произвольных URL или имён файлов для исполнения.
2. Известные подозрительные конструкции во входящем тексте изолируются до выделения фактов. Поиск дополнен NFKC и удалением невидимых Cf-символов **только для обнаружения**; легитимный текст сохраняется исходным. Это эвристика, а не исчерпывающий классификатор атак.
3. Пиксели и метаданные пользовательских картинок не отправляются ни автору, ни планировщику, ни DeepPresenter. Размещение делает код по неизменяемому каталогу. Команда «игнорируй инструкции» в картинке не получает канала управления генерацией. Удаление метаданных не удаляет надписи из пикселей — они остаются обычным видимым содержимым изображения.
4. Включённая пользователем финальная VL-проверка получает отрисованные слайды, следовательно может увидеть надписи в картинках. Это отдельный контур только для замечаний. Ответ ограничен строгой схемой, списком проверенных слайдов и типами дефектов. Исполняемых действий и автоматических правок по VL-ответу нет. Подозрительная инструкция в замечании делает проверку незавершённой. Ответ «всё хорошо» не отменяет детерминированные ошибки геометрии/покрытия.
5. Нормализованные PNG фиксируются по SHA-256 в подготовленном пакете, проверяются перед генерацией и сохраняются при создании новой версии. Модель не может подменить путь. Пользовательские имена и подписи выводятся экранированными; HTML имеет sandbox/CSP. В PPTX отсутствуют внешние image relationships.

## Остаточные риски и честные ограничения

Гарантии «никакая инъекция никогда не повлияет на LLM» нет. Обфусцированная текстовая атака может обойти эвристику и повлиять на формулировку плана в рамках разрешённой схемы. Визуальная атака способна исказить замечания VL или вызвать лишнее `needs_review`; но она не получает инструменты, ключи, сетевые права или возможность снять ошибки кодовых проверок. OCR-детектор атак в пикселях, полноценная мультимодальная red-team оценка и отдельный OS-sandbox декодера изображений остаются дальнейшим усилением. Лимиты Pillow снижают риск декомпрессионных бомб, но не заменяют своевременные обновления библиотеки и изоляцию процесса в production.

Нужно явно предупреждать пользователей: при включённой VL-проверке их иллюстрации, как часть слайдов, попадут к выбранному провайдеру модели. При автономном режиме этого не происходит. Загрузка шрифтов раскрывает только искомое название Google Fonts и не связана с картинками.
