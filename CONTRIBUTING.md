# Совместная разработка

Установка и настройка приложения: [TEAM_SETUP.md](TEAM_SETUP.md).

По текущему решению владельца работа над продуктом ведётся в `main`. Перед началом согласуйте непересекающиеся файлы и задачи с коллегами; не переносите экспериментальную ветку в рабочую версию. Не перезаписывайте чужие незакоммиченные изменения.

```bash
git switch main
git pull --ff-only
python -m pip install -r requirements.lock -r requirements-dev.txt
# Внесите изменения и запустите проверки ниже.
git status
git add path/to/changed-file.py
git commit -m "Describe the change"
git push origin main
```

Если удалённая ветка успела измениться, сначала разберите новые изменения; force push не используется. Форматирование и изменения поведения сохраняйте разными коммитами. Для просмотра большого изменения полезен `git diff --ignore-all-space`.

Изменение runtime-зависимостей отражайте в `pyproject.toml` и `requirements.lock`. Инструменты разработки закреплены отдельно в `requirements-dev.txt`, чтобы Ruff не становился runtime-зависимостью приложения. Изменение поведения отражайте в актуальных документах, сохраняя датированные отчёты как историю.

## Где находится код

- `studio/` — FastAPI, анализ, планирование, генерация, экспорты и проверки качества.
- `web/` — HTML/CSS/JavaScript интерфейса, без отдельной сборки.
- `prompts/`, `config/` — инструкции моделям, схемы настроек и политика приложения.
- `studio/_vendor/`, `vendor/` — включённые зависимости и модули коллеги; сохраняйте лицензии и сведения о происхождении.
- `tests/` — автоматические проверки с синтетическими входами и фиксированными ответами модели.
- `e2e/`, `test_support/` — сквозные браузерные проверки, изолированный сервер и строгий replay провайдера; не подключаются в приложении.
- `scripts/` — проверки, упаковка и вспомогательные инструменты. Исторические regression-скрипты могут требовать локальные данные прогонов; они не нужны для запуска приложения.
- `fonts/` — только включённые открытые шрифты с лицензиями.

Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md); последний аудит — [AUDIT_CODE_2026-09-26.md](AUDIT_CODE_2026-09-26.md). Датированные отчёты описывают состояние на момент проверки; текущие инструкции запуска — в TEAM_SETUP.md.

## Границы модулей

Владельцы функций и типы этапов перечислены в [STAGE_CONTRACTS.md](STAGE_CONTRACTS.md). Новую бизнес-логику не добавляйте в фасад `pipeline.py`; используйте соответствующий этап. Общие схемы и проверки размещайте ниже их потребителей, без обратных импортов. Циклы, включая импорты внутри функций, блокируются архитектурным тестом. Обновляйте версии кэшей при переносе их зависимостей.

## Проверка изменений

```bash
ruff format studio tests scripts test_support e2e
ruff check studio tests scripts test_support e2e
ruff format --check studio tests scripts test_support e2e
node scripts/ui_phase_labels_test.cjs
python -m pytest -q
```

Ruff закреплён на версии 0.15.7. Проверяются собственные Python-файлы; `studio/_vendor`, `vendor` и пользовательские `data` исключены. Включены базовые проверки ошибок, импортов и стиля (`E4`, `E7`, `E9`, `F`); это не проверка типов. Единственное исключение `E402` относится к диагностическому скрипту, который сначала настраивает путь импорта. CI запускает отдельные jobs линтера, Python-тестов и браузерных сценариев Chromium. Подготовка браузера, контракты replay и правила обновления ответов описаны в [TESTING.md](TESTING.md).

Запустите затронутые тесты, затем полный набор перед публикацией. Для UI и визуальных изменений дополнительно проверьте анализ и экспорт через браузер на своём шаблоне. В описании укажите, был ли прогон с реальной моделью: автономные тесты не доказывают качество модельного результата.

`data/`, `.env`, `.venv/`, сборки, пользовательские файлы и результаты тестов не коммитятся. Единственное согласованное исключение для credentials — общая `.env.team` в этом приватном репозитории. Не вставляйте её содержимое в Issues, PR, логи или скриншоты. Приложение и сторонние компоненты имеют отдельные лицензии: см. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

После изменений Python, промптов или конфигурации проверьте `/api/runtime`. `restart_required=true` блокирует новый анализ/генерацию до перезапуска сервера. Перезапускайте только после завершения активных и назначенных заданий. После запуска проверьте `/api/health` и `/api/runtime`.
