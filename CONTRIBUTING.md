# Совместная разработка

Установка и настройка приложения: [TEAM_SETUP.md](TEAM_SETUP.md).

`main` содержит общую рабочую версию. Для каждой доработки создавайте отдельную ветку и Pull Request:

```bash
git switch main
git pull --ff-only
git switch -c feature/short-description
# Внесите изменения и запустите проверки.
python -m pytest -q
git status
git add path/to/changed-file.py
git commit -m "Describe the change"
git push -u origin feature/short-description
```

На GitHub откройте Compare & pull request, опишите решаемую проблему и проверки. После ревью объедините Pull Request в `main`. Изменение состава зависимостей отражайте в `pyproject.toml` и `requirements.lock`. Изменение поведения пользователя отражайте в документации.

## Где находится код

- `studio/` — FastAPI, анализ, планирование, генерация, экспорты и проверки качества.
- `web/` — HTML/CSS/JavaScript интерфейса, без отдельной сборки.
- `prompts/`, `config/` — инструкции моделям, схемы настроек и политика приложения.
- `studio/_vendor/`, `vendor/` — включённые зависимости и модули коллеги; сохраняйте лицензии и сведения о происхождении.
- `tests/` — автоматические проверки с синтетическими входами.
- `scripts/` — проверки, упаковка и вспомогательные инструменты. Исторические regression-скрипты могут требовать локальные данные прогонов; они не нужны для запуска приложения.
- `fonts/` — только включённые открытые шрифты с лицензиями.

Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md); последний аудит — [AUDIT_CODE_2026-09-26.md](AUDIT_CODE_2026-09-26.md). Датированные отчёты описывают состояние на момент проверки; текущие инструкции запуска — в TEAM_SETUP.md.

## Проверка изменений

Запустите затронутые тесты и полный набор перед Pull Request. Для UI и визуальных изменений дополнительно проверьте анализ и экспорт через браузер на своём шаблоне. В описании укажите, был ли прогон с реальной моделью: автономные тесты не доказывают качество модельного результата.

`data/`, `.env`, `.venv/`, сборки, пользовательские файлы и результаты тестов не коммитятся. Единственное согласованное исключение для credentials — общая `.env.team` в этом приватном репозитории. Не вставляйте её содержимое в Issues, PR, логи или скриншоты. Приложение и сторонние компоненты имеют отдельные лицензии: см. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
