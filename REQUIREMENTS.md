# Требования, приоритеты и состояние реализации

Правило разрешения конфликтов: более позднее указание пользователя имеет приоритет. Наши рекомендации не становятся требованиями организаторов автоматически.

Источники: исходное ТЗ VK Tech; пользовательская сводка Q&A; уточнения пользователя в чате до 24.09.2026 включительно. «ЛЦТ2026 Шаблон презентации» не является контент-пакетом или четвёртым примером организаторов. В последующем пользователь загрузил его в приложение как произвольный шаблон: для этого запуска он служит входным PPTX на общих основаниях.

## Существенные разрешённые конфликты

| Ранее | Позднее | Принято в реализации |
|---|---|---|
| Ожидался отдельный контент-пакет | Q&A: отдельного пакета нет | Тема/текст + PPTX, необязательная аудитория и инструкции |
| 5 минут на одну колоду / весь pipeline | Последнее сообщение: анализ без лимита, три презентации суммарно за 5 минут | Подготовка отдельно, единое generation job с deadline 300 секунд |
| 10–15 слайдов | Количество задаёт пользователь; позднее уточнение: нехватка мест не должна останавливать анализ | По умолчанию 10; при конфликте сохраняются исходный лимит и предложенный расширенный план с предупреждением. Генерация большего числа требует подтверждения; выше 30 сохраняется только анализ |
| Только готовые layouts | Q&A разрешает и предпочитает новые композиции в дизайн-системе | Token composition + адаптация подходящих текстовых зон примеров |
| SmartArt в списке функций | Q&A: SmartArt — плюс | Не блокирует базовую версию |
| Редактируемость всех экспортов | Q&A: обязательно для PPTX | Native PPTX; DOM HTML; PDF |
| Многопользовательский режим объявлен требованием в нашем анализе | Установлено, что это лишь контекст объяснения версионирования | Многопользовательский режим не обязателен и не реализован |
| OpenDesign как потенциальное ядро | Согласованная архитектура: дизайн-слой отдельно от OOXML | Подключён конкретный craft-контекст; renderer и таймер собственные |

## Принятые рекомендации консультанта

Нет фиксированной отраслевой структуры. Планировщик получает роли context/insight/evidence/action/appendix. Факты не теряются при изменении порядка, детальные данные связываются с источником. Визуализация данных создаётся только из входной таблицы с сопоставимыми числовыми значениями. Автономный режим не придумывает причинность или рекомендации. «Один слайд — одна мысль» — содержательный ориентир, который должен проверяться моделью, а не только числом объектов.

## К следующему конкурсному прогону

1. Подключить выбранную лицензированную модель и измерить полный цикл трёх вариантов.
2. Проверить качество содержательного расширения короткого brief и обоснованность модельных заголовков.
3. Подключить реальный PPTX render + OCR/VLM; расширить corpus неизвестными шаблонами.
4. Улучшить сохранение визуальных паттернов и декора, проверить шрифты на машине презентации.
5. Перед финалом реализовать T2I и проверить совместимость всех модельных компонентов с VK Inference.

Требование исходного ТЗ о девяти результатах на трёх примерах покрывается тремя последовательными generation jobs. Последний лимит пользователя трактуется как 300 секунд на три варианта одного пользовательского шаблона, а не на девять колод сразу.
