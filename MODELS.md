# Модели и источники

В автономном режиме (`extractive`) генеративная модель не используется. Это инструмент проверки OOXML, orchestration, exports и security, а не замена конкурса моделей.

## Подключаемый API

Поддерживается chat-completions JSON endpoint `/chat/completions`. Endpoint, ID, ключ, лицензия и размер задаются сервером. Фактический model card нужно проверить до выбора модели; название модели не доказывает ни лицензию, ни размер. В этой поставке нет скачанных весов и нет привязки к придуманному VK URL.

Перед сетевым вызовом проверяется: open weights, 0 < B ≤ 35, Apache-2.0/MIT, корректный HTTPS endpoint (HTTP допустим только localhost), отсутствие URL credentials, запрет известных закрытых model families. Финал дополнительно требует точного hostname из `STUDIO_VK_ALLOWED_HOSTS`; allowlist заполняет оператор по данным организаторов. Redirects отключены.

Настройка должна подтверждать совокупный размер модели, включая экспертов MoE, если организаторы не указали иное. Нельзя указывать только число активных параметров для обхода лимита.

## Задачи

- Author: расширяет короткий brief проектными предложениями в timed generation stage. Предложения помечаются, не содержат новых чисел и имеют `source=model_proposal`. Подготовленный пакет не изменяется; ledger сохраняется в generation-content.json.
- Planner: выдаёт JSON с тремя `VariantPlan`. Допустимы только существующие fact/table IDs и разрешённые layouts. Проверяются покрытие, количество и новые числа в заголовках.
- Critic: проверяет текстовую связь заголовков с фактами и логические дефекты. Это текстовая LLM-проверка, не VLM.
- OCR, vision и T2I в текущем runtime не подключены. Нет скрытых запросов OpenAI/Anthropic.

## Локальная конфигурация NeuralDeep

23.09.2026: пользователь предоставил endpoint `https://api.neuraldeep.ru/v1/chat/completions` и ID `qwen3.8-27b`. Каталог `/v1/models` подтвердил этот ID; короткий реальный запрос вернул HTTP 200 и валидный JSON. Ключ хранится в игнорируемом `.env`, права `600`, не входит в Git/manifest/архив исходников и скрыт из `repr(Settings)`.

Метаданные: [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B), открытые веса, 27B, Apache-2.0. Проверка карточки не является аттестацией фактических весов на стороне провайдера. `owned_by=openai` в совместимом каталоге не используется как признак семейства модели.

Режим остаётся `selection`. В финальную VK allowlist этот сервер не добавлен. Провайдер сообщает vision-возможности, но наш вызов остаётся текстовым; это не VLM-аудит.

Согласно [документации NeuralDeep](https://neuraldeep.ru/llms-full.txt), управление reasoning у этого endpoint следует делать через `chat_template_kwargs.enable_thinking` либо alias `-noreason`, а не полагаться на `reasoning_effort`. В реальном тесте флаг `enable_thinking=false` не устранил reasoning: большой запрос вернул 3192 reasoning-токена и занял 147 секунд. Поэтому локальный `STUDIO_MODEL_ID=qwen3.8-27b-noreason` выбирает документированный вариант той же модели. Короткий тест alias вернул 0 reasoning-токенов; исходный `LLM_MODEL=qwen3.8-27b` сохранён. Это явная конфигурация, а не скрытая замена на другую модель при ошибке. Structured JSON контролируется настройкой и не заменяет локальную проверку фактов, количества и безопасных layouts.

OCR-контракт найден, транспорт написан и тестируется без сети; автоматическое подключение заблокировано отсутствием сведений о допустимости модели SotaOCR. См. OCR.md.

## Перед настоящим прогоном

1. Получить model card и лицензию выбранной модели.
2. Заполнить локальный `.env`, не коммитить ключ.
3. Проверить поддержку JSON response format, контекст и ограничения токенов у endpoint.
4. Выполнить 3×3 тест и максимум 15 слайдов на вариант.
5. Зафиксировать latency, usage, fallback rate и содержательные ошибки. Нельзя переносить результаты offline benchmark на LLM-режим.

Вопрос по лимиту image-модели 20B/35B остаётся открытым. Принято консервативное расширение ≤20B до официального уточнения. Данные о конкретной модели VK в сводке не считаются подтверждением её HTTP API или vision-возможностей.
