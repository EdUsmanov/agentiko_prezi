# Устойчивость пайплайнов и сохранение смысла при компоновке

## Что исправлено

- Отчёт об архетипах различает классификацию блоков и назначения слайдов редакторского плана. Новый отчёт сохраняет `reviewed_groups`; интерфейс умеет читать старые пакеты, где группы уже есть в narrative. Пустой или неполный отчёт больше не выглядит как успешная проверка нуля блоков.
- Табличные значения с обычными, неразрывными и узкими пробелами разбираются одинаково. Неоднозначная группировка и бесконечные значения не превращаются в вымышленные данные.
- Числовое сопоставление учитывает разделители тысяч, десятичную запятую и варианты минуса. Разные исходные факты и концы числовых диапазонов не склеиваются в одно число; оригинальные цитаты остаются неизменными.
- Таблица только со строкой «Итого»/«Всего» больше не превращается в пустую диаграмму. Смешанные единицы и вспомогательные столбцы сохраняются в подписях.
- Если в шкале шаблона отсутствует читаемый размер текста, компоновщик пробует минимальный допустимый размер. Он не обрезает текст и не отменяет проверку вместимости.
- Удаление дублей заголовка или ячейки учитывает отдельную смысловую подпись факта. Совпадение самого текста больше не удаляет название владельца/компонента.
- Подписи участников, компонентов и этапов сохраняются при переходе из специализированной композиции в общий макет, включая макеты с изображениями и нативные контракты полей. Пропажа подписи проверяется и в сцене, и в экспортированном PPTX.
- Выбор фонов отдаёт приоритет заполненным содержательным полям. Несколько небольших пустых карточек теперь учитываются вместе. Дублирующие друг друга поля одной карточки не считаются дважды.
- Этап различения вариантов больше не начинает каждый поиск с одного и того же фона: он учитывает уже выбранную последовательность. После этого этапа `plans.json` и отчёт о фонах отражают реальные экспортированные макеты.
- Сильно неравные общие панели не создают неподтверждённую иерархию для равноправных пунктов плана/участников/этапов. Если группы не соответствуют полям шаблона, их подписи и текст остаются вместе в общем поле.
- Редакторские инструкции дополнены проверкой авторского сценария, ясности фраз для аудитории и различия между реализованными и планируемыми возможностями.
- Управление адаптацией накопительных диаграмм и резервным выбором макета вынесено из низкоуровневых модулей. Это устраняет циклические зависимости, найденные полным набором тестов, без отключения архитектурной проверки.

## Причина подозрения на служебную инструкцию

В проверенном третьем слайде первого варианта текст про укладку материала в фирменный шаблон происходит из исходного пользовательского материала, а не из системного промпта. При переформулировке он стал похож на указание генератору. Отдельно подтверждена реальная потеря названий участников/компонентов при замене макета; она исправлена в коде и закрыта регрессионными проверками.

## Проверки

- Полный набор включает 803 backend-теста и 7 браузерных сценариев. Архитектурная проверка включена; обе обнаруженные циклические зависимости устранены.
- Целевые backend- и браузерные проверки, включая старые/новые/пустые отчёты архетипов.
- Реальный интерфейс действующего приложения: сохранённый редакторский пакет показывает 11 слайдов вместо нуля, без повторного анализа.
- Три изолированных прогона обычного приложения в локальном режиме: значения с неразрывными пробелами, диаграмма только с итогом, накопительная диаграмма только с итогом. По три варианта, без ошибок финального аудита; значения перепроверены в нативном PPTX.
- Сохранённый последний редакторский план пересобран штатными стадиями компоновки, экспорта и окончательной проверки. Проверены все 33 слайда, фактические подписи в PPTX, заполненность полей, различие геометрии и соответствие сохранённого плана результату. Во всех вариантах нет ошибок финального аудита и пустых содержательных полей. На 11 слайдов приходится 7–8 разных фонов, без одинаковых соседних фонов.
- Статические проверки: Ruff format/check для 210 файлов, 7 проверок подписей стадий интерфейса.
- Строгие синтетические HTTP-фикстуры обновлены только по контрольным суммам двух изменённых инструкций; исходные данные, схемы и ответы не изменены.
- Основной пакет исправлений (`00233fd`): **810 тестов прошли (803 backend + 7 браузерных), ошибок и пропусков нет**. Набор из 79 файлов выполнен в изолированных процессах без изменения исходников.
- Дополнительная правка удаления дублей с семантическими подписями: **79 целевых тестов прошли**, включая обе ветки композиции, изображения, архитектурные зависимости, экспорт и все браузерные сценарии. Новые регрессии проверяют заголовки, границы слов в имени владельца и совпадение с ячейкой таблицы.
- Сервер после безопасного перезапуска: `/api/health` — ok, `restart_required=false`; история загрузилась в настоящем браузере без ошибок JavaScript.
- Дополнительно повторён сохранённый прогон Т—Ж с восемью таблицами: все 33 слайда без ошибок аудита и пустых полей, пять разных фонов без повторов подряд. Ограничение разнообразия геометрии в этом исходном кейсе остаётся предупреждением, как и раньше.
- GitHub CI запускается push исправления; локальные результаты не подменяют его статус.

## Границы проверки

Локальный повтор использует сохранённый смысловой план. Он проверяет код компоновки и экспорт, но не заменяет проверку новых формулировок моделью. Внешний контрольный запрос не выполнен без дополнительного согласия на повторную передачу исходного текста и шаблона; автоматическая проверка разрешений остановила его до запуска. Набор браузерных тестов проверяет путь с DeepPresenter на записанных синтетических ответах модели.

Оригинальные пользовательские результаты не перезаписываются. Benchmark не запускался. Исправления не привязаны к имени или хешу шаблона. Нулевое число ошибок автоматического аудита не приравнивается к ручной приёмке дизайна: сохраняется статус `needs_review`.
