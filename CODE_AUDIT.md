# Аудит реализации, требований и архитектуры

Дата: 24.09.2026. Объект — текущая рабочая версия Forma, включая адаптированный DeepPresenter Design. Проведены ревью критического пути ввода/подготовки/планирования/композиции/рендера/выдачи, проверка контрактов, регрессионные тесты и живые прогоны. Это не независимый пентест, формальная верификация или обещание отсутствия любых ошибок.

## Исправленные проблемы

| Проблема | Исправление и проверка |
|---|---|
| Анализ SVG-only картинок падал с `no embedded image` | Удалены проверки `hasattr(shape, "image")`, вызывавшие свойство библиотеки. Картинки считаются по OOXML-типу, байты читаются из внутренних raster/SVG relationships. Пустые и внешние картинки не вызывают падение, сеть не используется. Защита копирования исходных картинок и групп сохранена |
| Аудит пропускал выход заголовка за плашку, сложные макеты отбрасывались, списки превращались в полотно | Parser v5: контейнерные границы, до шести body-зон, cover/heading/number slots; native bullets с шрифтом шаблона, emphasis и отдельные абзацы. Новый регрессионный корпус, локально отрисованы все 30 страниц пользовательского пакета |
| Геометрический/текстовый аудит воспринимался как визуальное одобрение | Добавлен отдельный opt-in critic изображений готового PPTX, проверка покрытия всех номеров и хеши PNG. Без VLM/при её ошибке API результат needs_review. Разрешение пользователя получено 24.09.2026; живые проверки и ограничения фиксируются в TEST_REPORT.md |
| Провайдер принимает один PNG, но отклоняет десять вложений | Пакеты до четырёх PNG, уменьшение пакета при HTTP 400/413 в том же дедлайне. Проверки полноты не ослабляются, 401 не повторяется |
| Модель выбирает геометрически допустимый макет с заголовком размера подписи | Сравнение с читаемым исходным назначением: деградация ниже min(16pt, размер baseline) заменяется исходной композицией без изменения текста |

| Остановка выглядела как замерший таймер, ошибка исчезала | Лоадеры вместо прогресс-баров/таймера; при ошибке анимация прекращается, сообщение остаётся под кнопкой, доступен повторный запуск. Время двух этапов выводится только с готовым результатом. Проверено Chrome smoke, включая retry/history/reduced-motion |
| Совпадающие композиции LLM отклоняли весь план | Политики в коде + fingerprints фактической геометрии + безопасное перестроение; тесты duplicate/single-fact/table |
| Технический парсинг выглядел как полный смысловой/визуальный анализ | Реальный template_analyst и content planning до таймера, отдельные статусы; VLM явно not_run |

## Соответствие действующему VK-кейсу

- Подготовка отделена от измеряемой генерации. Экспорт готовых трёх колод не переносится до таймера.
- Единый generation job, 300 секунд на все варианты/форматы; supervisor завершает POSIX process group. Просроченный результат не выдаётся за completed.
- Факты и источник сохраняются, модельные предположения маркируются. Однообразный план не уничтожается ради diversity.
- PPTX содержит native text/table/shapes и исходные master/layout/theme. HTML — живое содержимое, PDF/PNG по возможности из реального PPTX через LibreOffice.
- Палитра продукта VK Tech не навязывается пользовательским презентациям. Корпоративные fonts берутся из PPTX либо точного локального файла; при отсутствии полного шрифта подмена запрещена.
- Inference использует прежний model-policy gate; SDK-формат сообщений не означает использование закрытой модели. Финальная модельная инфраструктура проверяется отдельно оператором.
- OpenDesign — craft-слой. DeepPresenter — реальный, но ограниченно адаптированный Design loop. Штатный Research/HTML/VLM runtime и классический eval executor не включены.
- Текстовые смысловые проверки не выдаются за визуальные. token:auto/native fidelity замечания сохраняются.

## Проверки

Полный pytest и UI Chrome, проверки зависимостей и whitespace, живой синтетический и трёхшаблонный прогон. Окончательные числа/статусы записаны в TEST_REPORT.md; важны не только скорость и 0 геометрических ошибок, но и planning_source, model_degraded, contextual_audit и engine.status.

Неудачные внешние запросы и needs_review не скрываются из отчёта. Сетевой сбой провайдера не доказывает ошибку OOXML renderer; успешный маленький тест не доказывает SLA на любых больших входах.

## Что остаётся ограничением, а не исправленным дефектом

1. Полное соответствие произвольному сложному PPTX не гарантируется: image-driven layouts, сложные группы/SmartArt, текстовые логотипы и смешанная типографика поддержаны не полностью. Невместимый материал может требовать ручного решения.
2. VLM подключена, но её полнота обнаружения дефектов не гарантирована: на контрольном старом слайде пропущен выход заголовка за плашку. Выходной OCR, финальная T2I-генерация и PowerPoint/R7/Astra round-trip не реализованы/не проверены. Это не зелёные пункты приёмки.
3. Наличие финального VK endpoint, фактический размер/лицензия развёрнутой модели и качество коллегами проверенного PPTAgent не подтверждаются нашим тестом.
4. Изоляция parser/LibreOffice — не OS sandbox. Публичное размещение требует отдельного защищённого окружения, квот, authentication/tenant boundaries; текущий продукт single-user localhost.
5. Полноценный Markdown AST и расширенные визуализации другого хакатона — отдельная работа. Оценка в SECOND_HACKATHON_FIT.md, без изменения текущего конкурсного профиля.

Вывод: найденные воспроизводимые дефекты текущего контура исправляются и закрываются регрессионными тестами; отсутствующие крупные возможности и непроверенные внешние среды не объявляются реализованными.
