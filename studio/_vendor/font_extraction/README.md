# Извлечение шрифтов из презентаций — инструкция для агента

Это самостоятельный набор скриптов для PPTX/POTX. Репозиторий Агентико и
установка самого набора как Python-пакета не нужны. В архиве находятся весь
код извлечения, EOT/MTX-декодер с его лицензией, список двух внешних
Python-библиотек, описание контрактов и JSON-схемы.
В архив также включён готовый OOXML-датасет по 36 шаблонам (`dataset/`),
чтобы агент мог посмотреть формат до запуска. `MANIFEST.json` содержит SHA-256
всех файлов архива.

Для пересборки архива из каталога с распакованными скриптами:

```bash
python3 package.py --output font-extraction-kit.zip
```

## Подготовка

1. Распакуйте архив в любой каталог. Используйте Python 3.12–3.14. Для полного
   пайплайна нужны `httpx` и `pydantic` из `requirements.txt`; их можно
   установить в обычное локальное виртуальное окружение:

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

2. Нужен Node.js 24 в `PATH` для декодирования встроенных EOT/MTX. Сам
   декодер находится в архиве, `npm install` и собранный CLI Агентико не нужны.
   Если `node` находится вне `PATH`, задайте `NODE_EXECUTABLE`.
3. Запускайте скрипты из любого каталога; передавайте абсолютные пути в
   `--input` и `--output`, если запускаете их не рядом с презентацией.
4. Для загрузки недостающих шрифтов нужен доступ к Google Fonts, Fontsource
   и `download.microsoft.com` (пакет Aptos). `extract.py` работает без сети.
   Локальные шрифты ищутся через `fc-list`, если он установлен.

Далее команды показаны из каталога `font-extraction` после распаковки.

## Один файл → модель и файлы шрифтов

```bash
.venv/bin/python run_pipeline.py \
  --input /абсолютный/путь/к/template.pptx \
  --output /tmp/font-example
```

Вход: существующий `.pptx` или `.potx`. Выход:

```text
/tmp/font-example/
  font-model.json
  fonts/*.ttf или fonts/*.otf
```

Скрипт печатает в stdout короткий JSON со счётчиками, `complete` и путём к модели.
Саму модель читайте из `font-model.json`. В `slides[].elements` перечислены
только представленные на слайде текстовые роли и их семейства, начертания,
размеры в пунктах, источники и ссылки `assetId` на файлы. `usageBySlideKind`
сводит данные для первого и остальных слайдов. Если файл точного шрифта
недоступен, `status: missing` и запись в `unresolved` сохраняют факт без
подмены другим шрифтом. Полный контракт: [CONTRACTS.md](CONTRACTS.md).

Для каждого недостающего начертания скрипт последовательно проверяет Google
Fonts, Fontsource (открытые семейства вне каталога Google) и официальный пакет
Microsoft Aptos. Скачанный файл принимается только при совпадении имени,
начертания и разрешения `fsType`; SHA-256 записывается в модель. Поле
`fontAssets[].origin` показывает источник (`google-fonts`, `fontsource`,
`microsoft-aptos`). Шрифты, для которых нет доступного файла точного
начертания, остаются в `unresolved`; совпадение по похожему названию или
подмена метрик не считаются успехом.
Уже проверенные загрузки сохраняются в локальном кэше
`~/.cache/agentico/font-downloads` и используются при повторных запусках,
если источник временно недоступен. Кэш не входит в поставляемый ZIP.

Скрипт не кладёт шрифты Microsoft в поставляемый ZIP. Лицензия в официальном
архиве Aptos разрешает локальную установку, но не предоставляет права на
распространение шрифтов третьим лицам. Полученные файлы предназначены для
локального использования в соответствии с этой лицензией.

Например, титульный слайд может содержать:

```json
{
  "number": 1,
  "kind": "title",
  "elements": {
    "title": [{
      "family": "Play", "weight": 400, "style": "normal",
      "sizesPt": [60.0], "status": "downloaded", "assetId": "..."
    }]
  }
}
```

Это сокращённый фрагмент: фактический `FontUse` также содержит `script`,
`source`, `evidence` и `shapeIds`.

## Каталог → модели всех презентаций и отчёт

```bash
.venv/bin/python run_corpus.py \
  --input /абсолютный/путь/к/templates \
  --output /tmp/font-corpus > /tmp/font-corpus-result.json
```

Вход: каталог; обрабатываются прямые дочерние `.pptx` и `.potx` в порядке
имён. Выход:

```text
/tmp/font-corpus/
  summary.json
  summary.csv
  <имя-презентации>/font-model.json
  <имя-презентации>/fonts/*
```

Прогресс печатается в stderr, итоговый `summary.json` — в stdout. Ошибка
одного файла отмечается как `status: error` и не прекращает обработку других.
`status: ok` означает, что модель записана и файлы проверены по SHA-256;
недоступные начертания считаются отдельно. Если `.pptx` и `.potx` имеют одно
базовое имя, расширение сохраняется в имени выходного каталога.

## Каталог или файл → датасет без скачивания

```bash
python3 extract.py \
  --input /абсолютный/путь/к/templates \
  --output /tmp/font-dataset
```

Выход: `presentations.jsonl` (одна презентация в строке) и
`slide-fonts.csv` (одна строка на сочетание слайда, шрифта, роли и источника).
Текст слайдов в датасет не записывается. Этот режим не создаёт файлы шрифтов.

## Для автоматического агента

1. Запустите `run_pipeline.py` для одного референса либо `run_corpus.py` для
   набора. Проверьте код завершения: `0` — модель и все точные файлы получены;
   `3` — модель сохранена, но есть `unresolved`; `1` — ошибка разбора/записи;
   `2` у `run_corpus.py` — ошибка входа/запуска.
2. Прочитайте `font-model.json` или `summary.json`. В каталожном отчёте
   `modelPath` относителен к выходному каталогу.
3. Для каждого `slides[].elements[role][]` используйте `family`, `weight`,
   `style`, `sizesPt` и `assetId`. По `assetId` найдите `fontAssets[].path`.
   Роль, которой нет в `elements`, не создавайте в ответной модели.
4. Если `unresolved` не пуст, сообщите исходное семейство и начертание;
   для точного результата нужен легально доступный TTF/OTF. Не объявляйте
   другой файл точным совпадением.

Пример из корпуса: в `004-alfa-bank.pptx` титульный заголовок имеет
`Styrene A Bold`, 142,5 pt; на слайде 6 встречаются
`Styrene A Bold` (60 и 97,5 pt) и `Styrene A Regular` (28,5 pt).

Скрипты извлекают текстовые свойства из OOXML. Шрифт внутри растровой
картинки определить этим способом нельзя. Размер, отсутствующий в OOXML и
наследуемых стилях, не придумывается и в JSON опускается.
