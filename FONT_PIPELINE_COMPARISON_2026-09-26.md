# Сравнение шрифтовых пайплайнов — 26.09.2026

Решение: **не заменять пайплайн main целиком**. Использовать наследование свойств текста из набора коллеги, сохранив разрешение файлов, проверку начертаний, локальные Office-шрифты и экспорт main.

| Область | Пайплайн коллеги | Main и принятое изменение |
|---|---|---|
| Наследование OOXML | Роли, placeholder type/index, мастер, тема, свойства абзаца и presentation defaults | `font_manifest.properties` теперь использует этот resolver вместо собственного сопоставления placeholder только по idx |
| Стиль конкретного поля | Есть family/weight/style/size/source/shapeIds в модели использования | `native_style` сохраняет family, bold, italic, размер, цвет и источник; `Pattern.fields[].style` передаёт их сборщику |
| Файлы встроенных шрифтов | Декодер MTX уже был перенесён; для embedded assets вес берётся из OOXML-слота | Main сохраняет определение веса по бинарному файлу, проверку семейства и символов |
| Установленные шрифты | Поиск через `fc-list`, фильтрация по разрешению повторного распространения | Main находит шрифты macOS/Office и поддерживает local-only без включения font programs в выдачу |
| Скачивание | Google Fonts, Fontsource и Aptos | Оставлен существующий проверяемый путь main; сетевые источники в этом сравнении не запускались |
| Пригодность замены целиком | Не доказана; есть воспроизведённая регрессия Medium | Целиком не переносится |

## Воспроизведённый пример

Во временном PPTX использован настоящий `Montserrat-Medium.ttf`, вес **500**, помещённый в OOXML-слот `regular`. В самом тексте запрошен `Montserrat Medium`.

- `reference_font_assets` коллеги записал для встроенного файла вес **400**.
- `build_reference_font_data` счёл запрошенный вес 500 недоступным (`unresolved`). Сеть была отключена подставным resolver; `fc-list` отсутствует в этой macOS-среде.
- `build_font_manifest` main использовал тот же встроенный файл с весом **500**, без unresolved.

Это конкретный пример несовместимости, а не утверждение о низком качестве всего набора коллеги. Его `reference_font_usage_styles.py` совпадает по содержимому с уже включённым в main одноимённым helper из color-extraction-kit; повторная копия не нужна. Теперь этот код действительно используется и для шрифтового анализа, и для локальных стилей полей.

## Границы изменения

Сохраняется один доминирующий стиль конкретного поля. Полное смешанное форматирование каждого run, все межабзацные интервалы, маршрутизация восточноазиатских/RTL-шрифтов и variable fonts этим изменением не реализованы. Отсутствующее точное начертание поля помечается явно; оно не объявляется найденным.
