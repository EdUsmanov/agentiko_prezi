# Шрифт из пользовательского шаблона

Порядок выбора: встроенное начертание в PPTX/POTX → точное локальное совпадение → разрешённый каталог открытых шрифтов → ожидание недостающих TTF. Если найденный шрифт не покрывает символы нового текста, автоматически проверяется полное локальное начертание той же гарнитуры, затем поставляемый Montserrat подходящего веса. Замена отражается в предупреждении; покрытие всего текста проверяется повторно. Поиск выполняется при подготовке, вне общего лимита 300 секунд генерации трёх презентаций.

## Модель шрифтов по ролям

Независимая модель по подходу из набора коллеги: `font-model.json` содержит использование по слайдам/макетам, роль, семейство/начертание, размер, источник наследования, признак наблюдения или эвристики, статус `embedded / installed / downloaded / missing`, SHA-256 и вес/курсив разрешённого файла. Текст исходных слайдов и локальные пути в публичный отчёт не включаются. Из третьей поставки подключён MTX-декодер с MPL-2.0; весь пайплайн Agentico не переносился. Подход к получению точного TTF через Google Fonts CSS API адаптирован в наш загрузчик.

Разрешаются Latin-шрифты темы `+mj-lt/+mn-lt`, свойства runs, абзацев, плейсхолдеров и мастер-стилей. Для каждой роли выбирается наиболее используемое начертание: заголовок, основной текст, таблица, колонтитул. Выбранные файлы используются при измерении, аудите, HTML/PDF и отрисовке PPTX в LibreOffice. Исходная таблица соответствий и все недоступные начертания сохраняются. Отсутствующее начертание, не выбранное ни для одной выходной роли, отмечается предупреждением, но не блокирует генерацию: старый текст слайдов всё равно удаляется.

Это типографика **по ролям на уровне презентации**, не воспроизведение каждого исходного run или отдельной гарнитуры в каждом паттерне. Нет полной поддержки шрифтов SmartArt/внутренних chart parts, сложных письменностей и всех theme overrides. Полужирные смысловые акценты существующего компоновщика могут синтезироваться средствами экспорта; побуквенное совпадение начертаний не заявляется.

## Поддержано

- Чтение `p:embeddedFontLst` и font-relationships исходного PPTX. Поддержаны статический TrueType, несжатый EOT и EOT/MTX с TrueType-контурами. Извлекается используемое начертание, а не произвольный файл с похожим названием.
- Файл сохраняется в `data/jobs/<id>/embedded-fonts/<sha256>.ttf`, не устанавливается в ОС и не попадает в общий каталог других заданий. Приоритет встроенного файла действует даже при наличии одноимённого локального шрифта.
- Проверяются внутреннее название, ограничение размера 16 МБ, формат, таблица OS/2 и наличие нужных Unicode-символов. Перед генерацией сверяется hash. Исходные данные шрифта не изменяются.
- Один и тот же файл используется для измерений текста, PDF и HTML. Выбранная исходная embedded font part сохраняется в итоговом PPTX; остальные исходные font parts удаляются из результата.
- Проверка символов выполняется и при подготовке исходного текста, и перед экспортом модельного текста. Если встроена лишь часть алфавита, отсутствующие символы не заменяются квадратиками молча.
- U+2060 WORD JOINER и его устаревший эквивалент U+FEFF не требуют видимого глифа. Исходные факты сохраняются без изменения; при измерениях и экспорте эти управляющие символы не рисуются, а соединённые ими символы остаются вместе при переносе. Остальные Unicode-символы не удаляются целиком по категории Cf: буквы, диакритика, ZWJ и variation selectors не фильтруются этим исправлением. Это узкая поддержка Word Joiner, а не полная реализация Unicode line breaking. Источник: [Unicode, Word Joiner](https://unicode.org/versions/Unicode18.0.0/core-spec/chapter-23/).
- Локальный поиск учитывает семейство **и начертание**, регистр/разделители и пользовательские каталоги macOS/Linux/Windows. Bold не подменяет отсутствующий Regular. Новый TTF подхватывается при следующем анализе без перезапуска.

## Ограничения

PPTX нередко содержит только название, например `Montserrat Medium`, без данных шрифта. Из такого файла невозможно извлечь TTF. Это подтверждено для шаблона из неудачного пользовательского запуска: `embeddedFontLst` и `ppt/fonts/*` отсутствуют. Для него теперь доступно точное локальное начертание Montserrat Medium.

Сжатый MTX поддержан через отдельный процесс Node.js. Для него нужен `node` в PATH либо `STUDIO_NODE_EXECUTABLE`. На локальном стенде проверены Node 16.14.2 и bundled Node; для новых установок используйте поддерживаемый вашей инфраструктурой Node.js. XOR-защищённый EOT, EUDC, variable fonts, CFF/OpenType-контуры и font collections пока не поддержаны. Поддержка встроенных шрифтов **не означает поддержку любого PPTX**. В этих случаях показывается причина и проверяются остальные разрешённые источники.

Декодирование ограничено 10 секундами, 16 МиБ на вход/выход и каждый буфер декодера, 96 МиБ суммарных явных выделений типизированных буферов и 128 МиБ V8 heap. Последние два ограничения не являются общим OS RSS sandbox. Таймаут завершает дочерний процесс. Ключи модели, NODE_OPTIONS и NODE_PATH не передаются. После декодирования заново проверяются формат, fsType и фактическое начертание. Слот `regular` в OOXML не означает вес 400: для Jost Medium из пользовательского шаблона подтверждён вес 500 из OS/2. Исходные данные шрифта не переименовываются и не модифицируются.

Текущий набор экспортов включает HTML с данными шрифта и редактируемый PPTX. Поэтому извлечение допускает только `fsType=0`; ограничения preview/print-only, restricted, editable-only, no-subsetting и bitmap-only не обходятся. Это консервативная техническая политика, не проверка прав пользователя: сама возможность встраивания не заменяет лицензию на использование и распространение шрифта. Ограничения нельзя исправлять изменением битов в файле.

Локально найденные и скачанные шрифты пока не добавляются в PPTX: на компьютере получателя они должны быть установлены. Открытые шрифты используются в PDF/HTML; для локальных Microsoft-шрифтов действует более строгий режим ниже.

## Если шрифт отсутствует

При отсутствии нужного для выходной роли начертания подготовка переходит в `waiting_fonts`. Технический профиль, отчёт и входные данные сохраняются. Генерация заблокирована. Добавьте законно доступный статический TTF в `fonts/` или `data/local-fonts/` и нажмите «Проверить шрифты повторно» в интерфейсе или истории. Повторная проверка запускает подготовку на сохранённом входе; его целостность проверяется по SHA-256. Полный анализ пересчитывается, его отсутствие не маскируется. Приватный файл восстановления не отдаётся через API.

Другой вариант — сохранить PPTX с встраиванием **всех символов** и загрузить новый файл. Частично встроенный алфавит обнаруживается проверкой глифов. Для такого файла действует автоматическая замена, описанная выше; если даже резервный шрифт не покрывает текст, подготовка останавливается с объяснением. Полностью отсутствующее начертание по-прежнему требует разрешения через `waiting_fonts`.

## Автоматическая загрузка

`STUDIO_DOWNLOAD_OPEN_FONTS=true` включает поиск в официальном `google/fonts` на `raw.githubusercontent.com` (обычный запуск приложения включает его по умолчанию; тестовые Settings — нет). `false` отключает сетевой поиск. Используются только каталог `ofl`, подтверждённая SIL OFL, точное статическое TTF-начертание и проверка внутренних имён, веса, курсива, формата и fsType. Если в репозитории нет готового статического файла, запрашивается конкретный вес через `fonts.googleapis.com/css2`, затем TTF с `fonts.gstatic.com/s/`. Полученный файл должен быть статическим и без CSS unicode-range; локальная конвертация variable fonts не выполняется. Apache-каталог пока не поддерживается. Сеть недоступна или совпадения нет — понятный статус missing, а не подмена.

URL конструируется кодом из ограниченного имени; ссылки шаблона, редиректы и proxy env не используются. Для CSS-ответов также проверяется точный разрешённый HTTPS-хост; userinfo и явные порты запрещены. Ограничены размеры ответа и время загрузки. Наружу передаются название, вес и курсив искомого шрифта, не презентация и не содержимое документа. Кэш — `data/local-fonts/google/`, с лицензией, адресом источника и SHA-256; проверенный кэш используется повторно без сети. Лицензии скачанных файлов включаются в архив результатов как `FONT_LICENSES.txt`. Автоматически скачанные коммерческие шрифты и поиск на произвольных сайтах не допускаются.

## Aptos и локальные шрифты Office

Aptos 4.40 (28 TTF, включая Display, Narrow, Mono, Serif) подключён локально из [официального пакета Microsoft](https://www.microsoft.com/en-us/download/details.aspx?id=106087), SHA-256 ZIP `6528fd120e719a9f985e94214eca6887d1653b88456916a792a630b02e95b025`. Файлы и EULA находятся в `data/local-fonts/aptos/`, не в распространяемых исходниках. Поиск также учитывает DFonts установленного Microsoft Office на macOS без копирования файлов.

Повторяемая установка: после ознакомления с EULA выполните `.venv/bin/python scripts/install_aptos.py --accept-license`. Установщик проверяет фиксированный адрес, размер и hash; изменившийся пакет требует пересмотра лицензии и pin. При анализе Aptos не скачивается автоматически с Microsoft.

EULA этого пакета не предоставляет права распространения и исключает commercial software hosting services. `fsType=8` не отменяет этих договорных ограничений. Поэтому шрифты не встраиваются в выдаваемый PPTX, а PDF и HTML содержат только отрисованные изображения страниц; редактируемым остаётся PPTX. Для редактирования получателю нужен тот же шрифт. Это сознательное ограничение доступности/поиска текста в PDF/HTML. Для коммерческого размещения сервиса нужны подходящие права или другой шрифт, согласованный с пользователем. Лицензионные биты не изменяются.

Сейчас в поставку включены Play Regular и Montserrat Regular/Medium/Bold. Полный набор «всех часто используемых» шрифтов не заявляется; коммерческие шрифты не скачиваются автоматически. Дополнительный каталог не решает проблему неизвестного корпоративного шрифта без его данных.

Источники: [EOT specification](https://www.w3.org/submissions/EOT/), [OpenType OS/2](https://learn.microsoft.com/en-us/typography/opentype/spec/os2), [Microsoft: embedding fonts](https://support.microsoft.com/en-us/office/fonts/benefits-of-embedding-custom-fonts).

## Замена для языка нового текста

Полный локальный файл должен соответствовать исходному начертанию, быть статическим TTF с разрешённым встраиванием (`fsType=0`) и покрывать весь текст. Иначе используется поставляемый Montserrat Regular/Medium/Bold по весу исходного шрифта. Замена может изменить оформление, в том числе курсив; она раскрывается в предупреждении подготовки и в итоговом отчёте. Исходные шрифты остаются в `font-model.json`, фактически выбранные записываются в раздел `generation`. Проверка повторяется после работы редактора, поскольку модель может добавить новые символы.

Профиль с заменой, зависящей от текста конкретного задания, не сохраняется в общий кэш шаблонов: следующий документ на другом языке должен проверяться по исходным шрифтам.
