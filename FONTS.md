# Шрифт из пользовательского шаблона

Порядок выбора: встроенное начертание в PPTX → точное совпадение в локальном каталоге → объяснение, каких данных не хватает. Шрифт другой гарнитуры автоматически не подставляется. Название и источник показываются в интерфейсе; SHA-256 и источник сохраняются в подготовленном пакете и manifest.

## Поддержано

- Чтение `p:embeddedFontLst` и font-relationships исходного PPTX. Поддержаны статический TrueType и несжатый EOT с TrueType-контурами. Извлекается используемое начертание, а не произвольный файл с похожим названием.
- Файл сохраняется в `data/jobs/<id>/embedded-fonts/<sha256>.ttf`, не устанавливается в ОС и не попадает в общий каталог других заданий. Приоритет встроенного файла действует даже при наличии одноимённого локального шрифта.
- Проверяются внутреннее название, ограничение размера 16 МБ, формат, таблица OS/2 и наличие нужных Unicode-символов. Перед генерацией сверяется hash. Исходные данные шрифта не изменяются.
- Один и тот же файл используется для измерений текста, PDF и HTML. Выбранная исходная embedded font part сохраняется в итоговом PPTX; остальные исходные font parts удаляются из результата.
- Проверка символов выполняется и при подготовке исходного текста, и перед экспортом модельного текста. Если встроена лишь часть алфавита, отсутствующие символы не заменяются квадратиками молча.
- Локальный поиск учитывает семейство **и начертание**, регистр/разделители и пользовательские каталоги macOS/Linux/Windows. Bold не подменяет отсутствующий Regular. Новый TTF подхватывается при следующем анализе без перезапуска.

## Ограничения

PPTX нередко содержит только название, например `Montserrat Medium`, без данных шрифта. Из такого файла невозможно извлечь TTF. Это подтверждено для шаблона из неудачного пользовательского запуска: `embeddedFontLst` и `ppt/fonts/*` отсутствуют. Для него теперь доступно точное локальное начертание Montserrat Medium.

Сжатый MTX, XOR-защищённый EOT, EUDC, variable fonts, CFF/OpenType-контуры и font collections в извлечении пока не поддержаны. PowerPoint может создавать именно сжатый EOT, поэтому поддержка встроенных шрифтов **не означает поддержку любого PPTX**. В этих случаях показывается причина и проверяется точное локальное начертание. При его отсутствии анализ останавливается.

Текущий набор экспортов включает HTML с данными шрифта и редактируемый PPTX. Поэтому извлечение допускает только `fsType=0`; ограничения preview/print-only, restricted, editable-only, no-subsetting и bitmap-only не обходятся. Это консервативная техническая политика, не проверка прав пользователя: сама возможность встраивания не заменяет лицензию на использование и распространение шрифта. Ограничения нельзя исправлять изменением битов в файле.

Архитектура пока использует **одно доминирующее начертание** на презентацию. Смешанное оформление отдельными гарнитурами для заголовков/текста и автоматическое подключение всех шрифтов шаблона остаётся отдельным расширением. Локально найденные шрифты пока не добавляются в PPTX; на компьютере получателя они должны быть установлены. PDF/HTML содержат используемый шрифт.

## Если шрифт отсутствует

В PowerPoint включите сохранение шрифтов в файле и, когда доступно, вариант встраивания **всех символов**, а не только использованных. Повторно загрузите PPTX. Если шрифт не разрешает встраивание либо сохранён в неподдерживаемом формате, предоставьте законно доступный статический TTF через папку `fonts/`. Набор открытых шрифтов служит лишь резервом, а не источником стиля вместо шаблона.

Сейчас в поставку включены Play Regular и Montserrat Regular/Medium/Bold. Полный набор «всех часто используемых» шрифтов не заявляется; коммерческие шрифты не скачиваются автоматически. Дополнительный каталог не решает проблему неизвестного корпоративного шрифта без его данных.
