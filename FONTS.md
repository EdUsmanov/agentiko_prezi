# Шрифты

Анализ PPTX/POTX выполняет комплект `studio/_vendor/font_extraction` из пользовательского архива `font-extraction-kit (1).zip`. Точка подключения к приложению — `studio/templates/font_extraction.py`. Прежние модули извлечения удалены.

Комплект читает свойства текста и наследование стилей OOXML, включая тему, мастер, плейсхолдеры, таблицы, диаграммы и SmartArt. Для каждого слайда в `font-model.json` версии 2 он перечисляет роли, семейства, письменности, начертания, размеры и источник свойства. Текст слайдов в модель не записывается.

Файлы точных начертаний ищутся среди встроенных в презентацию шрифтов, установленных через Fontconfig, в системных каталогах и локальных `fonts/` и `data/local-fonts/`. При `STUDIO_DOWNLOAD_FONTS=true` недостающие варианты последовательно запрашиваются у Google Fonts, Fontsource и из официального пакета Aptos. Ссылки из PPTX для загрузки не используются. Найденный файл принимается после проверки семейства, веса, курсива и разрешений `fsType`. Если точного файла нет, модель сохраняет `unresolved`; другое семейство не объявляется совпадением.

Комплект записывает `font-model.json` и файлы `fonts/*.ttf|otf` в каталог подготовки. В модели файлы указаны относительными путями и SHA-256. Адаптер выбирает из модели начертания для заголовка, основного текста, таблиц, диаграмм и колонтитула; именно эти файлы используются для измерения и экспорта. После неудачного поиска и скачивания точного начертания адаптер явно подставляет ближайшее по весу и курсиву начертание того же семейства, затем семейства основного шрифта шаблона, затем комплектный Montserrat. Исходный `font-model.json` остаётся точным отчётом о шаблоне, а подстановка записывается отдельно в профиль и предупреждения результата.

Для POTX без исходных слайдов адаптер создаёт временные слайды по макетам и пропускает их через тот же набор. Дополнительный результат сохраняется как `layout-font-model.json`; `font-model.json` исходного файла при этом корректно содержит пустой список слайдов.

Символы нового текста проверяются перед компоновкой и экспортом. Если точное начертание из комплекта не покрывает символы нового текста (например, кириллицу в загруженном подмножестве Calibri), для выходного текста выбирается полное локальное начертание той же гарнитуры, а при его отсутствии — комплектный Montserrat подходящего веса. Исходный `font-model.json` при этом остаётся отчётом о шаблоне; замена раскрывается в анализе и предупреждениях результата. При последовательных подстановках отчёт показывает итоговое начертание, включая Bold. Если и заменяющий файл не покрывает текст, подготовка останавливается с перечнем отсутствующих символов. Для нескольких стрелок и маркера используется отдельно раскрываемая посимвольная подстановка Montserrat.

Для встроенных EOT/MTX нужен Node.js 24. Декодер поставляется с комплектом; приложение ограничивает объём входа и ответа, память Node и время процесса. Исходные EOT-части не копируются в готовый PPTX. Полученные файлы используются локально при подготовке и рендере; наличие того же шрифта на компьютере получателя влияет на отображение редактируемого PPTX.

Файлы Aptos не входят в исходный код. Полученные файлы этого семейства считаются локальными: HTML и PDF выпускаются без передачи файлов шрифта. Использовать пакет Microsoft следует в рамках его лицензии.

Комплект анализирует свойства текста OOXML. Он не распознаёт шрифт внутри растрового изображения и не обещает точное воспроизведение каждого исходного текстового фрагмента в новой композиции.
